Purpose

When a target FULL CUDA graph pads its request count, DPSyncState.num_reqs describes graph capacity rather than the number of scheduled requests. Reusing that capacity for uniform drafter steps makes active DP ranks select larger draft graphs than needed.

This PR keeps the DP-wide maximum real request count alongside graph capacity and uses it for uniform drafter dispatch. It also shrinks online dummy-rank DFlash batches coherently across input preparation, graph dispatch, attention metadata, EPLB preparation, and draft generation. Startup graph capture retains its required capacity.

Test Plan & Result

The performance validation below uses the official nightly build at the PR base. This PR uses the same nightly plus only the four Python files changed by this PR; the runtime SHA-256 values were verified after the overlay was applied.

GPU environment

  • Model: DeepSeek-V4.1-Flash.
  • Hardware: two non-production nodes, one arm per node, with 8x NVIDIA H20 96GB per arm.
  • Image: vllm/vllm-openai:nightly-77154ca6116ae34cbfe314beef1016bde9b63989
  • Baseline: the official nightly without a source change.

vLLM Startup Command

vllm serve /data00/models/DeepSeek-V4.1-Flash \
  --host 0.0.0.0 \
  --port 8010 \
  --served-model-name deepseek-v4.1-flash \
  --trust-remote-code \
  --tokenizer-mode deepseek_v41 \
  --attention-backend FLASHMLA_SPARSE_DSV41 \
  --kv-cache-dtype fp8_ds_mla \
  --data-parallel-size 8 \
  --enable-expert-parallel \
  --max-model-len 131072 \
  --max-num-batched-tokens 2048 \
  --max-num-seqs 96 \
  --compilation-config '{"cudagraph_mode":"FULL_DECODE_ONLY","cudagraph_capture_sizes":[16,32,64,128,256,512]}' \
  --speculative-config '{"method":"dspark","num_speculative_tokens":5,"draft_sample_method":"probabilistic","rejection_sample_method":"block","enable_adaptive_verification":true}' \
  --gpu-memory-utilization 0.95 \
  --disable-uvicorn-access-log

vllm bench serve \
  --backend openai \

GSM8K Test

Both arms were evaluated simultaneously with EvalScope 1.9.1 using the full 1319-sample zero-shot GSM8K test split and identical generation parameters.

evalscope eval \
  --eval-type openai_api \
  --api-url http://127.0.0.1:8000/v1 \
  --api-key EMPTY \
  --model deepseek-v4.1-flash \
  --model-id deepseek-v4.1-flash \
  --datasets gsm8k \
  --dataset-args '{"gsm8k":{"few_shot_num":0}}' \
  --eval-batch-size 8 \
  --generation-config '{"temperature":0.2,"top_p":0.95,"max_tokens":8192,"timeout":3600,"seed":0,"reasoning_effort":"high"}' \
  --work-dir ./gsm8k-results \
  --no-timestamp
  • Baseline: 1270/1319 (96.29%).
  • This PR: 1264/1319 (95.83%).
  • Paired outcomes: 1257 both correct, 13 baseline-only correct, 7 This PR-only correct, and 42 both wrong.
  • Exact two-sided McNemar test: p=0.26318; no statistically significant difference.
  • API errors: zero in both arms. Baseline had three and This PR had five outputs reach the 8192-token limit.
  • EvalScope performance: mean latency 7.58 -> 7.13 s (-5.90%); average output throughput 52.17 -> 56.16 tok/s (+7.65%).

AI assistance

AI assistance was used to instrument the DP drafter path, identify the online dummy-rank graph mismatch, implement the follow-up optimization, run GPU validation, and summarize the results.
