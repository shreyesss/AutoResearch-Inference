# C03 — Use logical requests rather than target padding for drafting

Status: **Screen deferred; no promotion**. Updated: 2026-10-21 (Asia/Calcutta).

**Claim:** Carry real request counts alongside graph capacity and use them coherently in draft inputs, metadata and dispatch, retaining full startup capture capacity.

**Why:** Target CUDA graphs pad requests to a capture capacity. Reusing this padded capacity for DP draft dispatch schedules unnecessary rows, including on lightly loaded/dummy ranks.

**Research finding:** All three audits converge on #58984. Fresh shows source conflicts with the pinned image, so this is an adaptation rather than a demonstrated clean cherry-pick.
