This is a refactored version of
#60267
from
@hjjq
.
Main changes from that PR:
Move out of MRV2 since it's a generic collective, make compatible with elastic ep
Don't use
batch_isend_irecv
which is actually slower with gloo
Generalize to any DP size (not just power of 2)
Also use for the post-step DP state sync
Remove the env var, just use it unconditionally
Gloo's all_reduce on the small CPU tensors used for DP synchronization is latency-bound and grows roughly linearly with the DP size. Add
cpu_all_reduce_()
to
vllm.distributed.utils
: recursive doubling within power-of-two blocks of ranks, then one concurrent exchange between blocks, so any group size completes in log2(largest power-of-two factor) + 1 rounds. Block sums are added in a fixed order, so results are bitwise identical across ranks.
It calls
ProcessGroup.send/recv
with group-local ranks, so it also works with stateless (unregistered) groups such as the engine-core DP group and elastic EP's DP group.
It is used automatically (no env var) for:
the V2 worker's DP padding/cudagraph sync, via
GroupCoordinator.cpu_all_reduce_()
the engine-core DP state sync,
ParallelConfig.sync_dp_state()
Performance
Standalone microbenchmark: p50 latency (µs) of an in-place SUM all-reduce of a 6×N int32 CPU tensor (the V2 DP metadata shape) over gloo, one process per rank, on GB200 nodes with gloo over the nodes' Ethernet NIC. Each method was run for 5,000 calls, interleaved in random order; the value is the median across ranks of per-rank p50.

[Perf] Low-latency CPU all-reduce for DP metadata syncs
…
7b544ec
Gloo's all_reduce on the small CPU tensors used for DP synchronization is
latency-bound and grows roughly linearly with the DP size. Add
`cpu_all_reduce_()` to vllm.distributed.utils: recursive doubling within
power-of-two blocks of ranks, then one concurrent exchange between blocks,
so any group size completes in log2(largest power-of-two factor) + 1
rounds. Block sums are added in a fixed order, so results are bitwise
identical across ranks.

It calls ProcessGroup.send/recv with group-local ranks, so it also works
with stateless (unregistered) groups such as the engine-core DP group and
elastic EP's DP group.

It is used automatically (no env var) for:
- the V2 worker's DP padding/cudagraph sync, via
  GroupCoordinator.cpu_all_reduce_()
- the engine-core DP state sync, ParallelConfig.sync_dp_state()

p50 latency of a 6xN int32 all-reduce, gloo all_reduce -> cpu_all_reduce_:
- 1 node:   8 ranks 1690us -> 326us; 12 ranks 2749us -> 400us
- 2 nodes:  8 ranks 1977us -> 362us; 12 ranks 3005us -> 536us
- 4 nodes: 16 ranks 5354us -> 546us
- odd sizes (1 node): 7 ranks 850us -> 365us; 15 ranks 3920us -> 1042us
