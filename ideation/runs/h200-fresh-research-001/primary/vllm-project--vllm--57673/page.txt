Overview
Rework this as an opt-in SM90 backend with centralized selection and separate Triton prefill/decode, as requested in review. DeepSeek V4.1 TP8/TP4 keeps its 8/16 local query heads instead of padding to 64.
Claims
Select with
--attention-backend TRITON_MLA_SPARSE_DSV41
; default backend selection is unchanged.
Eligible verification-query pairs share sparse KV reads. Other decode shapes use the direct Triton decoder.
H20×8/TP8 output throughput improves 5.4–8.7% in the measured workloads, with lower p95 TTFT and end-to-end latency.
Validation
Same image and flags, changing only the attention backend. Source and native libraries built from
0c16eee3
; DSpark adaptive/5, Humming 0.1.16/BF16, batch 8192, max 64 sequences,
fp8_ds_mla
and fixed KV budget 22,191,197,696 bytes/GPU.
EvalScope 1.11.1 with a reasoning-field timing fix: 200 streaming requests per point, identical frozen prompts, isolated prefixes, 1024 output tokens with EOS ignored. All requests succeeded; no timed compilation, cache hits or preemptions observed in the included samples.

Details
The direct decoder and packed-KV loader come from
#59418
by luoyuctl (
eddfa5ed50c1
), with three page-size parameters specialized as
tl.constexpr
. They are isolated in the first commit. This PR adds independent backend integration, native-head prefill and query pairing; it does not add
#59418
's automatic FlashMLA dispatch. Shared-decoder landing order still needs coordination. Query-union prior art:
#55372
. Unlike
#54592
, prefill keeps BF16 queries. Reported gains measure the whole backend, including the shared decoder and DSpark interactions.
Requires SM90, BF16 queries, 512D heads/64D RoPE and packed
fp8_ds_mla
KV. Prefill stays outside FULL CUDA Graphs. The context limit is 1M; measured performance inputs are 8K/32K. TP4 full-model, actual 1M inputs and comprehensive multimodal evaluation are not qualified.
Driver-memory maxima sampled every 60 seconds changed by −2.04 to +1.40 GiB/GPU; the 32K cases used about 1.4 GiB/GPU more. These are sampled values, not exact peaks or a memory-saving claim.
