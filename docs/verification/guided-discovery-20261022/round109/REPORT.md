# Round 109 — static precision allocation for the remaining FP8 SWA cache

## Decision and permission boundary

**Retain SP109-01 as a deferred, quality-gated experiment proposal. No typed hypothesis has been created, implementation changed, or improvement measured.** The intervention is a static per-target-layer choice between the existing 528-byte MXFP8 sliding-window record and a new 288-byte NVFP4 record. Keep compressed-cache representation, neural weights, indexer selection policy, window length and draft model fixed in the initial arm.

The active brief prohibits GPU/model work and training, but does not impose universal bitwise target equality on every research direction. The original TreeSpark plan's exact greedy gate remains appropriate for a decoder advertised as lossless. This proposal changes target activations, hence potentially the target distribution and downstream routes. It is **not** lossless speculation or an implementation-equivalence claim. A future quality budget must be agreed and evaluated before promotion; this packet invents no acceptable accuracy loss. The baseline is the planned Flash1017 revision `1bae0e...`, callgideon/vllm `c455786...`, TP1/DP4/EP4, B200, native DSpark5. Actual backend/format selection is not attested.

## Paper-led selection

One structured-date arXiv query (2026-09-01 through 2026-10-23 exclusive, limit12) returned12 papers, all abstract-screened. Selected [MultiAlloc, arXiv2610.18642v1](https://arxiv.org/abs/2610.18642v1) for fulltext reading: it separates offline precision allocation from online inference. The reusable component is **static layer precision selection under a measured memory budget**. The paper also assigns a high-precision token-preservation budget and selects tokens within groups; that component is not included here. Therefore this proposal cannot inherit the paper's joint-method results.

The paper's calibration uses KV quantization perturbations weighted by gradients of next-token loss, collected with a forward-backward pass. It does not update model parameters, but it still requires model execution and is prohibited in this CPU/source-only task. Its sensitivity is a ranking surrogate, expressly not an absolute downstream-accuracy predictor. Calibration is workload-specific; task-disjoint validation and later on-policy rollout remain necessary. A cheaper forward-only layer ablation would be our alternative, not the paper's gradient method or its guarantee. No calibration, model inference or allocation search ran here. The paper's A100/batch1 results exclude calibration cost and do not predict B200/Flash1017 performance. No author implementation repository was identified in the selected fulltext.

## The missing target operation

Round83 already established that the Mega backend resolves generic FP8 configuration to `nvfp4_ds_mla`: **compressed KV is288B NVFP4 while SWA is528B MXFP8**. Enabling that existing compressed format is not this proposal.

Pinned sources establish the following chain:

| Stage | Current contract | Required selective extension |
|---|---|---|
| Layer initialization | `attention.py` chooses SWA528, compressed288 under the Mega format; SWA block size32 | Explicit immutable per-layer SWA format, default existing; keep semantic head512 and positions |
| SWA producer | Fused Q/RoPE/KV-insert C++ op emits512 FP8 bytes+16 UE8M0 scales after RoPE | Add FP4 encoder at the same numerical/input boundary; preserve query-side work and slot mapping; specify rounding/scales, padding and nonfinite handling |
| Decode reader | FlashMLA API rejects `model_type==V41_FP4` for original/main cache; only originalFP8 plus extraFP4 is instantiated | New originalFP4 specialization/dispatch and cache metadata, including pure-SWA layers; not deletion of a guard alone |
| Reader internals | Format templates exist, but scale offsets/TMA maps and mixed-cache assumptions distinguish originalFP8 from extraFP4 | Audit both formats, extra presence, two-CTA scale staging, gather alignment and sink/output fusion before reuse |
| Prefill reader | Same gather wrapper consumes compressed and SWA caches;288B dispatch already supports `gather_lens` and offset | Reuse this component after validating SWA-tail addressing;288B forces Triton while current FP8 may use CuteDSL, so prefill can regress |
| Physical allocator | Per-layer `state_content_bytes`, page padding, record-stride LCM and cache groups determine actual allocation | Construct separate correct specs/groups; retain indexer/compressed/draft pages and cache identity; validate actual block layout before claiming saved capacity |

Relevant precise sources are retained in `sources/` with exact blob locators and hashes. FlashMLA is pinned `vllm-project/FlashMLA@5dceadbd...`. Its API line379 is a concrete current incompatibility, not evidence FP4 is intrinsically invalid. Existing compressed NVFP4 encoding/decoding is an implementation starting point, not a complete SWA port. The existing prefill gather is a useful rescued component: no need to invent a second generic dequantizer.

The target uses one latent as both K and V. Calibration must observe the actual shared tensor and its complete QK/PV effects. Separate K/V memory costs must not be doubled. The paper's separate perturbation terms cannot be assumed to rank this tied-latent computation identically; a profile of the actual graph or an explicitly conservative surrogate is required. Round83's retained value-error counterexample already explains why preserving attention scores alone cannot qualify this change. No additional synthetic quality test was manufactured.

## Physical cost and contrary evidence

The exact config has40 target layers, window128, index-topk512; target layers0/1 are pure SWA. For an affected layer reading128 valid SWA entries and512 compressed entries, logical record payload is215,040B now versus184,320B with SWA288: **30,720B /14.29% less logical record payload**. A pure-SWA layer's corresponding fraction is45.45%. These are conditional integer counts, excluding Q/output, repeated accesses, cache hits, page padding, descriptors and compute. They are neither measured HBM traffic nor a service speedup. Fewer valid SWA entries lowers the mixed-cache fraction; zero SWA reads gives zero saving.

Physical allocation is not this payload calculation. The planner uses either a sum of individually padded layer pages or the largest group sum rounded to the LCM of stride alignments. SWA specs can remain prefix-cacheable depending on replay policy; allocated residency cannot be inferred solely from window128. Some mixed configurations may pad away savings, change group structure or fall back to a different allocation mode. Existing generic `kv_cache_dtype_skip_layers` support is not wired into these inspected target format choices. PR42345/42890 concern generic mixed-format page support, not this missing SWA codec/API.

A bounded local corpus scout produced734 body matches because SWA/FP4 occur in broad descriptions. A title refinement produced32 metadata hits; only four selected PR bodies were read. This is not734 implementation reviews or repository-wide absence proof. Important contrary evidence: [SGLang37138](https://github.com/sgl-project/sglang/pull/37138) describes all-pool MXFP4 on old DeepSeek-V4-Flash/H20: more capacity but reported decode throughput **−3.3%**, small-batch kernel latency **+8–12%**, and prefill regression. Those are author-reported, different-target results, not reproduced here, but they directly refute an automatic “half the bits means faster” premise. [FlashInfer6001](https://github.com/flashinfer-ai/flashinfer/pull/6001) confirms its FP4_CA format keeps SWA528 even when no compressed cache is present; it is not an existing all-FP4 SWA implementation. No selected PR diff/head was hydrated because the pinned target already resolves the present-interface question and donor bodies were used only as scoped corroboration/counterevidence.

FP4 conversion may add unpack/scale work while attention arithmetic, indexer, projections, experts and all40 layer traversals remain. The current FP4 reader dequantizes into BF16; no new native FP4 QK/PV throughput is assumed. Quality-safe layers may be few, and recent tokens may be especially sensitive. No numerical ROI or latency forecast is justified.
