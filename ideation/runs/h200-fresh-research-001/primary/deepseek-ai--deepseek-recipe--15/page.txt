Motivation
In
v4/mod.rs
's
render_message
, the assistant branch guards reasoning rendering with
thinking_mode && index > 0
. But every message in the
render_conversation
loop is a
history
turn (the next assistant turn is appended after the loop), so the guard has no principled meaning for assistant messages: an assistant turn carrying
reasoning_content
at index 0 renders
<｜Assistant｜></think>{content}
and
silently discards its reasoning
, while the identical turn at any later index renders
<｜Assistant｜><think>{reasoning}</think>{content}
. Whether history reasoning survives depends solely on whether the conversation happens to start with another message.
Reachable via an Anthropic Messages request without a
system
field whose first message is an assistant turn with a
thinking
block, or directly via
Conversation(messages=[AssistantMessage("hi", "I should help")])
with default thinking mode.
(Note:
render_reasoning_effort
also uses
index == 0
, but legitimately — the effort directive belongs to the first system slot.)
Changes
Drop the
index > 0
condition from the assistant reasoning branch. No API change.
Testing
New unit test renders the same assistant-with-reasoning turn with and without a leading user message and asserts the reasoning appears in both prompts. Red/green verified:
fails on the previous implementation
(
assistant reasoning at index 0 must render identically
), passes with the fix.
cargo test -p deepseek-recipe-encoding --locked
: pass.
