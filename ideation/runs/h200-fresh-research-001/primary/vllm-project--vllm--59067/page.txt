Purpose
Fix an MRV2 KV-sharing fast-prefill correctness bug when a scheduled batch
contains both LoRA and non-LoRA requests.
The fast-prefill path compacts the model input to
logits_indices_padded
, but
the LoRA Punica metadata was still built for the original full token batch.
The existing kernel call then used the first
x.size(0)
entries of the full
mapping while retaining the full-batch sorted indices and token counts.  For a
base request followed by a LoRA request, this can route the compact rows to the
wrong adapter and can cause an out-of-bounds access in the LoRA shrink kernel.
This PR is limited to eager execution. It selects the LoRA mapping with
logits_indices_padded
, rebuilds the Punica metadata for that compact
mapping, and scopes it only to the Gemma3n/Gemma4 cross-decoder call.
The original full-batch metadata remains active for the self-decoder and other
model operations.
