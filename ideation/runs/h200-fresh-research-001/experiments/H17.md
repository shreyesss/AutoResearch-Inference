## Model statement and experiment

Test exact-size registration of CPU-offloaded Engram tables only after resolving whether this deployment uses private DP shards or shared host storage. The launch arguments establish offload and embedding_across_dp, but do not establish allocation ownership, rounding or backing. PR #59849 separates two effects: exact sizing reduces host allocation, while registration type changes lookup performance in its GB10 experiment. If the live private-table path still rounds allocations, port that allocation change with safe fallback and unchanged sorting and NUMA placement. Compare against exact-size cudaHostAlloc and supported existing THP settings. Predict serving benefit only if host pressure or exposed lookup latency falls; memory savings alone do not establish lower H200 cost per token.

**Control:** Attested allocation with matched NUMA placement and sorting. Include exact-size cudaHostAlloc as an attribution control and the strongest supported existing THP/placement configuration as a practical comparator.

**Correctness:** Check exact table bytes and lookup outputs at shard and allocation boundaries, sorted/unsorted paths, empty and uneven batches, registration fallback, teardown and repeated allocation/free. Exercise graph replay and distributed storage lifetime. If outputs or math change unexpectedly, require numerical and quality qualification rather than acceptance statistics. Map relevant cases to G01-G05 once supplied.

**Cost:** Cheap allocation inspection, then moderate allocator/lifetime validation. Host-memory savings are not GPU KV savings or an automatic node-price reduction. Use C8*T/(3600*Nqualified), with C8 unknown.

**Held out condition:** Primary native agent-f75 and Mooncake at seq64. Hold out cold/warm allocation phases, long and ragged prefills, repeated versus random row IDs, and simultaneous memory pressure from both replicas. Keep random-row microbenchmarks separate.

**Inconclusive if:** Storage ownership, physical-memory accounting or registration telemetry is unresolved, host pressure is unrepresentative, or serving differences remain within drift.

**Metrics:** Denominator: private offloaded table allocations eligible for exact registration; numerator: successful exact registrations, with fallback counts. Track logical bytes, actual registered bytes, physical host usage without double-counting shared mappings, faults, pressure and NUMA traffic. Measure lookup rows and exposed lookup time, TTFT tails, request TPOT, exact tokens, qualified goodput, KV/preemption, draft counters and replay lag on all ranks.

**Rejects if:** Tables are already exact/shared with no relevant delta; registration is unsupported; lookup gains remain entirely hidden; no serving value appears under adequately covered relevant conditions; or lifetime/correctness failures occur. Record memory-only savings separately.

**Supports if:** The eligible branch activates and reduces actual allocation waste; serving qualification additionally requires lower exposed stalls or lookup time and better unprofiled metrics than the strongest comparator. Confirm small effects with at least five alternating paired full-run blocks and held-out checks.

**Treatment:** First inspect effective allocation and source presence. If eligible, change only exact-size registration and fallback handling; qualify before unprofiled serving tests.
