Overview
With
dp_shared_memory
, node-local DP ranks share one registered
/dev/shm
mapping for the Engram host tables (2 layers x 94.4 GiB on DeepSeek-V4.1-Flash). Lookups are random row reads and on GB200 they are bound by GPU TLB misses: the registered mapping uses 64K pages.
This PR allocates the shared table as host-NUMA cuMem instead, which the GPU maps with 2M pages. Rank 0 creates it and broadcasts a FABRIC handle; the other node-local DP ranks import and map it. Where FABRIC handles are unavailable (probed once: create + export), the existing
/dev/shm
path is used and logged. Rank 0 decides the backing and broadcasts it so every rank runs the same collectives. A mapping failure on any rank raises on all ranks.

GPUs map host-NUMA cuMem with 2M pages instead of the 64K pages of a
registered /dev/shm mapping, so TLB-bound Engram row lookups get 2-3x
faster. Rank 0 exports a FABRIC handle that node-local DP ranks import;
platforms without FABRIC handles keep the /dev/shm path.
