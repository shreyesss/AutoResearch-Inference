Medium Risk
Changes vLLM CUDA graph sizing for a production AgentX benchmark recipe; wrong capture bounds could affect latency/throughput or startup, though scope is limited to H200 launcher env and defaults elsewhere stay at 1.

Overview
Raises the CUDA graph capture floor for H200 DeepSeek-V4.1-Flash DSpark AgentX runs so low-concurrency points size graphs for concurrent AgentX subagents instead of undersized captures.

The shared dsv41flash_fp4_vllm_mtp.sh script now seeds --max-cudagraph-capture-size from optional DSV41_MIN_CUDAGRAPH_CAPTURE_SIZE (still doubling up to CONC * 6 and 2048). The H200 Slurm launcher sets that env to 64 for dsv41flash jobs, lifting c1/c2/c4 from 8/16/32 while c8+ behavior is unchanged. Speculative DSpark settings, synthetic AL 3.51, Engram UVA, and trace replay are untouched.

Documentation (EN/ZH) and perf-changelog.yaml record the H200 recipe change. New pytest coverage in runners/test_dsv41flash_capture.py asserts the capture-size matrix and that eval vs throughput speculative config stays correct.
