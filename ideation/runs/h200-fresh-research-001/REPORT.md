## What was actually researched

All **5,532 URL/title identities across the 13 CSV repositories** were indexed without inheriting the old B200 applicability filters. SGLang, Humming and vLLM's FlashMLA fork were added explicitly. There are **108 selected primary PR/issue page snapshots across 16 repositories**, **69 downloaded patches**, and read-only snapshots of the running H200 configuration and installed code. These counts describe source acquisition; they do not mean every line of every patch or every indexed issue received equal scrutiny. Each repository has an explicit use/defer decision in the coverage table.

Discovery includes nine mechanism/hardware/failure query families across all CSV repositories, live repository searches, Fathom/Serper searches, three bounded SGLang PR/issue searches, OpenAlex literature searches, and focused implementation/discussion reads. Sources were followed from performance claims to counterexamples and then to installed dispatch: Humming schema failures, candidate-indexer single-request regressions, DeepGEMM synchronization, and Engram's resolved shared-memory branch materially changed the shortlist.

The initial four-day opening-feed refresh ran before the URL-first clarification. It is retained as provenance, not a prerequisite for future runs. `github.index_csv` now stores URLs, titles and identities in a separate discovery index; `github.catalog` searches it; `github.open` fetches one selected opening record and optional PR refs. Discussions and patches are fetched when they can change a decision. Unchanged indexing of all 5,532 rows took **0.093 seconds**, made **zero network requests**, and added **zero primary bodies**. URL leads never become quotation evidence merely because they appeared in search.

Coverage is bounded: public API limits and some HTTP 429 patch responses are recorded; captured discussion is HTML-visible, not an exhaustive review/reply archive. Empty searches and absent citation edges are uncertainty. The repository coverage file and receipts make these gaps inspectable. No claim of exhaustive live GitHub history or publication novelty is made.

## Findings that changed the order

**Humming is a staged comparison.** [vLLM #59488](https://github.com/vllm-project/vllm/pull/59488) supports separating backend, indexed/grouped execution and activation precision. [Issue #60600](https://github.com/vllm-project/vllm/issues/60600) exposes the installed 0.1.16 schema mismatch; its closure and promised 0.1.17 fix do not update our image. Block-FP8 and MXFP8 are not interchangeable Hopper settings. [Humming #38](https://github.com/vllm-project/humming/issues/38) supplies strong counterevidence about group-scale synchronization overhead. A direct Marlin versus Humming comparison at unchanged precision is cheaper and more interpretable than a bundled upgrade.

**Small ports remain useful, with modest expectations.** [Plan sharing #58818](https://github.com/vllm-project/vllm/pull/58818) removes redundant planning, while [mHC #61461](https://github.com/vllm-project/vllm/pull/61461) changes SM90 launch parameters for one to eight rows. Their vLLM source hunks apply to disposable copies of the installed source. Runtime compatibility and correctness remain untested. H20 synthetic-acceptance service results and isolated kernel percentages are not H200 serving predictions. A logical k5 verification batch has six tokens per request, but graph padding can put the actual mHC launch outside the small-row band.

**The Hopper indexer opportunity is no longer implementation-free speculation.** [#62000](https://github.com/vllm-project/vllm/pull/62000) gathers candidate KV before scoring; [#62463](https://github.com/vllm-project/vllm/pull/62463) scores candidates directly through page tables. They are alternative treatments against dense scoring. The former reports a single-request regression; the latter has small sample counts and pending coverage. Both need adaptation to this installed revision. Treat long-context benefit, short-context fallback, live graph lengths, causal bounds and quality as separate questions.

**Cross-engine evidence supplies concrete tests, not transferable headline gains.** [SGLang #41251](https://github.com/sgl-project/sglang/pull/41251) bundles multiple H200 changes. [#41561](https://github.com/sgl-project/sglang/pull/41561) motivates fusing top-k with page mapping, but only where downstream consumers do not still need logical indices. [#40860](https://github.com/sgl-project/sglang/pull/40860) uses a different indexer-cache representation. A matched SGLang engine control can establish a service gap; it cannot attribute that gap to one kernel.

**DeepEP and FlashInfer remain meaningful, conditional lanes.** [DeepEP #693](https://github.com/deepseek-ai/DeepEP/pull/693) pipelines direct-NVLink dispatch on H100. Measure compatible backend activation before testing the triple-buffer change. [FlashInfer #6343](https://github.com/flashinfer-ai/flashinfer/pull/6343) provides native-MXFP4 SM90 MegaMoE and EP4 support, but its named benchmark geometries differ from our E384/H5120/I2304/top6 model. [#6517](https://github.com/flashinfer-ai/flashinfer/pull/6517) adds a necessary workspace cleanup repair and weight-layout/scale requirements; its H200 push-dispatch tuning leaves EP4 unchanged. [vLLM #62603](https://github.com/vllm-project/vllm/pull/62603) is a block-FP8 integration, not a drop-in native-MXFP4 adapter.

**A small prefill kernel idea needs a numerical gate.** [DeepGEMM #452](https://github.com/deepseek-ai/DeepGEMM/pull/452) changes the contiguous SM90 MQA epilogue; installed source still has the old form. Its broad claim about all finite floating-point inputs is too strong: the saved [CPU counterexample](prefill-mqa/numeric-claim-check.json) shows doubling a large finite float can overflow. This does not demonstrate real model failure. It means range, nonfinite, rounding and selected-token checks must precede any speed claim; paged decode is outside the change.

## Mechanism design and evaluation

The frozen rubric rewards baseline value, H200 applicability/correctness, discriminating experiments, evidence and practical cost. Novelty is descriptive, not a veto. Evidence extraction, proposal generation and critique use separate calls through the existing research tooling. [MODEL_REVIEW.md](MODEL_REVIEW.md) records every outcome, including deferred candidates, missing evidence and the requested-count shortfall. Root engineering priority is reported separately from model eligibility; neither is experimental validation.

Three initial critics exceeded the CLI's input limit after cross-repository retrieval expanded their prompts. The tooling now retains packet and cited sources, limits extra excerpts and duplicated metadata, and explicitly lists omitted retrieval IDs. Full evidence remains archived. Recovery uses immutable descendant cards and `revisit`; failed runs are preserved. The prefill evidence run also rejected a nine-character quote under the minimum-length rule; a new packet expands that exact excerpt without changing the claim. These are documented repairs, not silently successful runs.

Each experiment card separates the upstream inefficiency, upstream fix, root prediction, baseline eligibility, strongest comparator, activation denominator, mechanism measurement, competing explanation and support/reject/inconclusive rules. No fixed quota of accepted ideas is forced. Planned tests carry explicit scope in persistent hypothesis memory; no runtime test outcome is invented.

The enhanced evaluator is carried forward with H200 corrections: preserve seq64 as control; test any seq128 change separately; compute TPOT from actual output tokens rather than SSE chunks; retain all-rank metrics and graph-mode coverage; distinguish activation, correctness, mechanism and unprofiled service value; use paired full-run replication and held-out E1/E2 conditions; keep profiler points out of the frontier. [G01–G05](../pr-evaluation-audit-001/REPORT.md) remain scoped correctness gates. Actual node price and product SLO are unset. Diagnostic thresholds are labeled provisional, and B200 cost/capacity numbers are not reused.

The [validation receipt](validation.json) passes: 53 software tests, final evidence/card quote checks, unchanged frozen inputs, local documentation links and secret-value scan. GPU fixtures, candidate images, deployment, generation and performance confirmation are future execution work. This run does not establish a production speedup.
