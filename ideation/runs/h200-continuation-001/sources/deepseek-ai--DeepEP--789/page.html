EngramBuffer: single-node NVLink support without RDMA devices?#789
Copy link

Description

peters
opened on Oct 20, 2026
Issue body actions

EngramBuffer initialization fails with CPU- or GPU-backed storage on a single NVLink node. Ordinary NCCL all_reduce passes on both ranks. This was a DeepInfer preflight; no model weights were loaded.

Environment

  • DeepEP 93eb6eb238127e96c6d7a4a625a6dad158348509, pinned by DeepInfer 8b16149741a4935e1dec8cea27853f273b374c5b.
  • RunPod container, 2 × B300 SXM6 AC; nvidia-smi topo -m reports NV18 between GPUs.
  • Python 3.12, PyTorch 2.13.0+cu132, loaded NCCL 2.32.3 (verified with ncclGetVersion).
  • Driver 595.91.07; CUDA compiler 13.3.33 with cuda-compat-13-3 selected at runtime.
  • Host NICs appear in /sys/class/infiniband, but the container has no /dev/infiniband device nodes.

Reproducer, reduced to the failing constructor from the tested probe. Save as repro.py in an environment with the pinned DeepEP build:

import sys
from datetime import timedelta
import torch
import torch.distributed as dist
import torch.multiprocessing as mp
from deep_ep import EngramBuffer


def worker(rank, cpu_storage):
    torch.cuda.set_device(rank)
    dist.init_process_group(
        "nccl", init_method="tcp://127.0.0.1:29741",
        rank=rank, world_size=2, device_id=torch.device("cuda", rank),
        timeout=timedelta(seconds=90),
    )
    group = dist.group.WORLD
    value = torch.tensor([rank + 1], device="cuda")
    dist.all_reduce(value)
    assert value.item() == 3
    print(f"rank {rank}: all_reduce passed", flush=True)
    gpu_bytes, storage_bytes = EngramBuffer.get_storage_size_hint(
        group, [256], 256, 8, 4, torch.bfloat16, 0
    )
    qps, depth, restrict = EngramBuffer.get_theoretical_config(group, 1, 8, 4)
    buffer = EngramBuffer(
        group, gpu_bytes, storage_bytes, cpu_storage, qps, depth, restrict,
        allow_hybrid_mode=True, explicitly_destroy=True, num_gpu_timeout_secs=30,
    )
    buffer.destroy()
    dist.destroy_process_group()


if __name__ == "__main__":
    mp.spawn(worker, args=(sys.argv[1] == "cpu",), nprocs=2, join=True)

Run separately:

python repro.py cpu
python repro.py gpu

Both tested storage modes fail at csrc/kernels/comm/context.cpp:125:

(allow_hybrid_mode ? props.railedGinType : props.ginType) != NCCL_GIN_TYPE_NONE
NCCL GIN is unavailable.

Is single-node NVLink-only Engram supported, or is exposed RDMA/GIN required even for GPU-backed storage? If required, documenting that prerequisite would help. Related: #629 concerns ElasticBuffer; this reproduces in EngramBuffer with allow_hybrid_mode=True.
