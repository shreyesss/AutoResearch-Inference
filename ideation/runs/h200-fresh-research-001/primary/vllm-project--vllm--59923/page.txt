Purpose
DeepSeek-V4.1's Engram tables are already MXFP8 (FP8 rows with one ue8m0 scale per 32 values) and
wkv
is an MXFP8 GEMM, but the lookup dequantizes each row to BF16, DP replicas all-gather those 512-byte rows layer by layer, and
wkv
quantizes them right back. This PR keeps rows packed from the host table to
wkv
.
Packed rows, direct MXFP8.
The lookup copies each row's 256 FP8 bytes and 8 scale bytes as they are, and one unpack kernel writes them in FlashInfer's MXFP8 activation layout (F8_128x4 scales).
wkv
takes them as a
QuantizedActivation
, so both the dequant and the requant are gone, and the output is bit-identical.
One all-to-all per prefill step.
EngramBatch
looks up every local Engram layer into one packed buffer and exchanges it with a single all-to-all, which sends each rank only its own tokens (264 instead of 512 bytes per head row, 1/DP of an all-gather), then unpacks all layers in one launch.
Peer exchange for decode.
Below 128 tokens per rank,
EngramPeerExchange
replaces the hash all-gather and the per-layer row all-gathers: ranks publish ids in symmetric memory, look up their head shard for every peer's tokens, and read their own tokens back from the peers after a barrier. All layers share one lookup and one unpack launch.
The batched path serves DP-sharded tables (
embedding_across_dp
without DP-shared memory) with TP = 1,
head_dim % 128 == 0
, no LoRA (it wraps
wkv
after construction), and a
wkv
kernel that takes F8_128x4 scales (reusing
can_fuse_query_quant
). The peer exchange also needs SM100, CPU offload, and 2/4/8 fully connected GPUs; without it every slot uses the all-to-all, which on DEP4 HBM tables at 1–127 tokens per rank is 19–58 us faster than the BF16 path. Everything else, including TP, DP-shared tables, single replicas and ROCm, keeps the existing BF16 path unchanged. Communication stays on the current stream and
wkv
still runs in
Engram.forward
.
Also changed along the way:
EngramBatch
is an
nn.Module
, so the peer exchange's pointer tables are model buffers that level-2 sleep restores.
fused_q_kv_rmsnorm_quant
and the Engram unpack kernel share the F8_128x4 scale offset and size helpers.

d593d7f
.

only drops paths that DEP + THP never takes and keeps its
wkv
outputs bitwise identical (see Test Result).

wkv

[Perf][DSv4.1] Exchange packed FP8 Engram rows across DP and feed wkv…
…
d593d7f
… MXFP8

DP-sharded Engram tables now look up rows as packed FP8 values plus ue8m0
scales and unpack them straight into FlashInfer's MXFP8 activation layout,
so the lookup no longer dequantizes to BF16 and wkv no longer requantizes.

- EngramBatch stages every Engram layer together: one all-to-all for slots
  of at least 128 tokens per rank, and a symmetric-memory peer exchange
  (EngramPeerExchange) below that on SM100 with CPU offload.
- Unsharded tables (DP-shared memory, single replica) use the same path
  without an exchange for 128+ tokens.
- The BF16 per-layer path, including the prefetch stream, is unchanged and
  still serves TP, LoRA, and other wkv backends; its DP exchange switches
  from all-gather to all-to-all at 128+ tokens per rank.

…
3724967
…ify it

- EngramBatch now serves only DP-sharded tables (TP1, FlashInfer MXFP8 wkv,
  no LoRA) and always stages MXFP8: the peer exchange below 128 tokens per
  rank when available, all-to-all otherwise. TP, DP-shared tables and
  single replicas keep main's BF16 path, and its DP row exchange is back

- Pad unowned and padding rows with scale 0 instead of 127; their values
  are zero, so wkv outputs stay bit-identical.
