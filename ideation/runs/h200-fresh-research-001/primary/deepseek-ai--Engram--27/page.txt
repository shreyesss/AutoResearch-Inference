Problem and change
Engram.__init__
currently always constructs a dense
MultiHeadEmbedding
. Experimenting with a frozen mmap/host-storage gather therefore requires allocating the default table first and replacing it afterward.
Add an optional
embedding_factory
argument to
Engram
. The callable receives the original
list_of_N
and
D
and returns an
nn.Module
. The default is still
MultiHeadEmbedding
, retaining the original state-dict keys, initialization and trainable weights. Hash addressing and downstream gates/projections/ShortConv are unchanged. This avoids the default table allocation when a caller supplies an alternate backend.
The hook does not add a library dependency, implement offloading/compression, or change default training/inference. Backends own loading, shape/dtype/device compatibility, training behavior and resource cleanup. README documents the contract and an example.
Validation
python -m unittest discover -s tests -v
: 3 tests passed.
Default and explicit original factory have identical state dictionaries and retain trainable embedding parameters.
An injected frozen gather receives the expected original head sizes/dimension, avoids default-table allocation, and produces byte-identical full Engram output through the existing gates and ShortConv.
A factory returning a non-module fails clearly.
Tests use tiny local IDs and original
_get_ngram_hashes
; only tokenizer/hash-map construction is substituted to avoid downloads. No trained checkpoint, tokenizer fidelity, backbone logits, quality or GPU-performance claim is made.
Separately, I tested a native mmap backend through this hook: default table allocation was avoided and full CPU module output matched byte-for-byte. A pinned unchanged-source integration harness also checks Python/native storage × float32/float16/bfloat16 (six cases):
source-linked report
. Those random-weight checks are interface evidence, not learned Engram compression results. No external backend code is required for this PR's tests.
Local environment: Python3.12.14, PyTorch2.14.1, NumPy2.5.4, sympy1.14.0, transformers5.20.1, tokenizers0.23.3, macOS26.6.2 arm64/Apple M5, CPU.
git diff --check
and semantic Ruff on the added tests passed.
Opening as a draft for feedback on whether this small extension point fits the demonstration API.
