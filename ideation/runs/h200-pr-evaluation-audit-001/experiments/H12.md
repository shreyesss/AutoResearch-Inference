# H12 — Preserve cache affinity at the final DP rank

Lane: **main**. Live-layout priority: **12**. Status: conditional plan; no GPU test or measured gain.

## Problem and causal hypothesis

Endpoint/session affinity can be lost when API processes independently select internal DP ranks. A load-aware tie-break can recover warm prefix locality.

## Applicability to our H200 deployment

Trace endpoint, API PID and final DP rank; verify current selector lacks equivalent tie-break and actual requests traverse it. Preserve cache salt/tenant boundaries and load priority.

## Isolated control and treatment

A: existing endpoint router and internal selector. B: #52464 internal tie-break only. API1 is diagnostic, not the production comparator.

## Evaluation and predicted mechanism

E1: native agent-f75; E2: frozen Mooncake median/burst/cache-heavy. H200 capacity discovery and held-out confirmation in PROTOCOL.md.

Measure: Final-rank affinity, token-weighted hits, queue skew, CPU routing overhead, TTFT tails and qualified goodput.

## Why an additional evaluation is or is not needed

Reuse E1 shared-prefix and E2 cache-heavy/burst, plus existing session client at low load. No new harness.

## Decision and falsification

Apply [the preregistered protocol](../PROTOCOL.md). Confirm path and missing behavior before spending GPU time. Support requires correctness, predicted mechanism movement and a useful held-out SLO outcome. Reject an active, well-measured change with no useful endpoint gain or a correctness/tail regression. Mark absent-path, underpowered or failed-replay cases inapplicable/inconclusive; do not label them disproven. Correctness lanes establish only scoped correctness.

## Evidence limits

Inherited H100 evidence showed only partial low-load recovery and flat/negative high-load results. Must not sacrifice load balance for hits.
