Purpose
On SM90, FlashMLA's sparse decode tiles query heads by 64 (the WGMMA M dimension). A DeepSeek V4.1 TP8 rank owns only 8 heads (16 at TP4), so it pads them to 64 and spends most of the tensor-core work on padding. This adds a Triton sparse decode kernel that tiles heads by 16 with
tl.dot
(mma.sync), reads the existing packed FP8 MLA cache directly, and recovers parallelism by splitting the key set across programs, merging the partial results with log-sum-exp.
Why it is faster at small batches.
At a few decode tokens per step, FlashMLA launches roughly one CTA per token and each CTA does 64-head work for 8 real heads. This kernel launches
tokens × splits
programs, each doing 16-head work over its share of keys. The best split count depends on both token count and key width: 32 splits at ≤3 tokens fills the GPU, but by 8 tokens 8 splits wins because the merge cost and per-program gather overhead dominate.
_pick_config
encodes this measured table. At larger batches the step becomes gather/dequant-bound rather than MMA-bound, so removing the padding no longer helps and FlashMLA is kept.
Dispatch
(automatic, no flag): SM90, 8 or 16 local heads, decode only, and
Layer key width (SWA + compressed top-k)

low-concurrency decode
. It does not depend on context length, since sparse attention reads a fixed number of keys per token. Prefill always uses FlashMLA.
JIT warmup:
both launches register every split config,
