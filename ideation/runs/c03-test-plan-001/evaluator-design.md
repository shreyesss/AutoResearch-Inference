Some but insufficient stronger opportunities mean low-exposure/inconclusive, while zero after adequate complete observation means inactive in that workload. These are declared coverage floors, not a statistical proof that every future workload activates the mechanism. ## Metrics and predeclared decision

Primary: `score.json.metrics.output_speed_sla.sufficiently_long_outputs.itl_p50_ms` for **Mooncake median at 0.5x**, outputs >=50 tokens. Lower is better. This preserves the exact existing scorer and cohort selection.

The installed AIPerf's ITL is `(last_content_time-first_content_time)/(server_output_tokens-first_content_chunk_tokens)`, falling back to N−1 when the first-chunk count is missing/inconsistent. TTFT is request start to first content, including reasoning. Usage-only terminal chunks are excluded from request latency. Thus label this **token-normalized post-first-chunk ITL**, not individual token spacing or raw SSE chunk gaps. Source: existing `.venv-aiperf/lib/python3.12/site-packages/aiperf/metrics/types/inter_token_latency_metric.py:23–33,63–102`, `ttft_metric.py:44–56`, `request_latency_metric.py:36–49`. Preserve the first-chunk count distribution and fallback/warning coverage in both arms so chunk bundling cannot masquerade as work reduction.

For each full paired block, compute `gain = 100*(1−B_ITL/A_ITL)`. Use the arithmetic mean of five paired percent gains. Draw 10,000 resamples of five complete block indices with replacement using Python `random.Random(20261020)` with `randrange(5)` for each of five indices per draw; take percentiles 2.5 and 97.5 of the sorted resampled means, linearly interpolating at index q*(10000−1), as the 95% interval. For each tail, compute paired regression `100*(B_tail/A_tail−1)` and use exactly the same sampled block indices and percentile rule. These are per-endpoint intervals, not a claim of simultaneous 95% familywise coverage. A block is the unit, not requests, ranks or tokens. The confirmatory decision occurs once after five valid blocks. If precision is insufficient, report inconclusive; any further fixed-size campaign requires a new predeclared addendum, not repeated testing until a pass.

Invalid-block replacement rule: if either arm fails a predeclared measurement-fidelity/identity requirement, retain both original arms and invalidate that whole pair with its reason. Repeat only after identifying and resolving a recorded external measurement-fidelity/identity cause; suspected candidate-induced errors or correctness regressions must be investigated and cannot be erased or replaced as noise. Then repeat the entire pair using the same seed and arm order under fresh run IDs. Allow at most two replacement pairs in the five-block campaign; a third invalid pair stops it as inconclusive. Never retain only the favorable valid arm or replace a pair because B was slow. A completed service-SLO-ineligible result is not an invalid block when fidelity passes. Correctness failure is a stop, not a replaceable block.

- **Confirmed useful latency benefit:** applicability/activation/correctness pass; actual executed drafter work decreases; the entire primary 95% interval is >=2%; and the upper 95% paired bounds on median-workload TTFT p99 and E2E p99 regressions are <=3%. Preserve measurement-fidelity gates; no new service gate failure may be hidden. For already failing SLOs, report their unchanged ineligibility and absolute values. Burst must show no new correctness/fidelity failure and no >3% observed tail regression in the screening pair; uncertainty is reported until repeated.
- **Mechanism works, useful endpoint gain rejected for this scope:** valid coverage and correctness, but the primary upper 95% gain bound is below 2%. A confidently negative effect is a regression. Keep the successful row-reduction finding separate.
- **Mechanism falsified:** adequate stronger opportunities but no executed-row/bucket reduction, despite correct instrumentation. Smaller counters alone do not support it.
- **Inactive/not applicable:** equivalent behavior already present, or no eligible opportunity in the fixed tested workloads with adequate complete observation. Do not claim universal disproof.
- **Inconclusive:** interval spans the 2% practical threshold, missing rank/graph evidence, too few eligible events, unexplained acceptance/first-chunk changes, mismatched runtime/cache state, failed replay fidelity or inadequate held-out precision.

Also report long-output ITL p90/p95/p99, all-output distributions, TTFT/E2E, exact lengths, errors, good fraction and qualified goodput, acceptance/proposed/accepted/verify deltas, prefix-hit share, preemptions, KV capacity, startup time, graph inventory and rank utilization. Acceptance is mechanism/context evidence, not an accuracy endpoint. Keep the existing length-aware goodput distinct from AIPerf's native goodput (`ops_aiperf/analyze.py:500–512`). Exclude existing default $36/hour cost fields from conclusions; node pricing is outside this experiment.
