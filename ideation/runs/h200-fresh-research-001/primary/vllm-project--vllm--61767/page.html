This is a refactored version of #60267 from @hjjq.

Main changes from that PR:

  • Move out of MRV2 since it's a generic collective, make compatible with elastic ep
  • Don't use batch_isend_irecv which is actually slower with gloo
  • Generalize to any DP size (not just power of 2)
  • Also use for the post-step DP state sync
  • Remove the env var, just use it unconditionally

Gloo's all_reduce on the small CPU tensors used for DP synchronization is latency-bound and grows roughly linearly with the DP size. Add cpu_all_reduce_() to vllm.distributed.utils: recursive doubling within power-of-two blocks of ranks, then one concurrent exchange between blocks, so any group size completes in log2(largest power-of-two factor) + 1 rounds. Block sums are added in a fixed order, so results are bitwise identical across ranks.

It calls ProcessGroup.send/recv with group-local ranks, so it also works with stateless (unregistered) groups such as the engine-core DP group and elastic EP's DP group.

It is used automatically (no env var) for:

  • the V2 worker's DP padding/cudagraph sync, via GroupCoordinator.cpu_all_reduce_()
  • the engine-core DP state sync, ParallelConfig.sync_dp_state()

Performance

Standalone microbenchmark: p50 latency (µs) of an in-place SUM all-reduce of a 6×N int32 CPU tensor (the V2 DP metadata shape) over gloo, one process per rank, on GB200 nodes with gloo over the nodes' Ethernet NIC. Each method was run for 5,000 calls, interleaved in random order; the value is the median across ranks of per-rank p50.

  • gloo: dist.all_reduce (current main)
  • [Perf][V2] Add custom CPU DP metadata all-reduce #60267: the original PR (VLLM_DP_METADATA_TRANSPORT=gloo-tree); power-of-two sizes only
  • this PR: cpu_all_reduce_

Where #60267 applies (power-of-two sizes), this PR has 5–18% lower latency. Gloo's latency grows roughly linearly with the number of ranks, while this PR adds about one round per doubling plus one round for the odd factor.

Correctness: tests/distributed/test_cpu_all_reduce.py (sizes 2, 3, 4, 6, 8, 9, 12; exact match vs dist.all_reduce, bitwise-identical float results across ranks, and a stateless process group). tests/v1/distributed/test_async_llm_dp.py with DP=4 passes with the multiprocessing backend (ray backend not tested).
