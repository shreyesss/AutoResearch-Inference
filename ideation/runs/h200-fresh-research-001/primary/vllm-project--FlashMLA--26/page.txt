Summary
Tensor-parallel deployments can leave only 8, 16, or 32 query heads per rank. SM90 sparse prefill previously required 64 or 128 heads, forcing callers to pad queries and compute unused heads.
Add a native SM90 kernel for 8/16/32 heads with QK dimensions 512 and 576.
Support strided query/output head slices, allowing direct writes into padded activation buffers.
Preserve attention sink, per-query top-k length, max-logit, and LSE semantics.
Adapt dispatch and shared parameters to the current
legacy::sm90
layout, including fused FP8 API initialization.
Explicitly reject multiple KV heads.
The existing 64/128-head paths remain supported. SM100 head-count support remains unchanged. Callers must pass the actual head count to use the new kernel.
Validation
Full extension build for SM90a, SM100a, and SM103a passed.
155 tests passed on H20, covering correctness, CUDA Graph replay, strided buffers, invalid indices, empty inputs, and API validation.
Compute Sanitizer: 63 boundary cases passed with zero memory errors.
All 24 benchmark configurations passed comparisons against padded FlashMLA.
On H20, compared with padding to 64 heads:
8/16 heads: 1.78–2.25× faster.
32 heads: 1.04–1.11× faster.
