## Decisive source boundary

I separately checked the original, v2, split-K and fused prefix/suffix variants: their prefix addressing still uses `base_slot + offs_n`. They keep query scores/softmax/output separate; the intended reuse is KV loads, not equal attention outputs. Query/head/bounds masks are not the target’s per-query TopK membership masks.

Target `_decode_compressed_kv_and_topk` reads each query’s selected indices and its request’s block table, yielding physical slots/lengths. `_forward_decode_mega` passes compressed and SWA regions separately, with positions, sink and fused RoPE/output quantization. The native kernel’s sink normalization includes the additional sink denominator contribution. A future grouped-prefix/suffix adapter must apply that contribution exactly once per query and preserve the original typed occurrence multiset. Same physical prefix owner is useful grouping evidence but cannot authorize adding unselected keys, deleting repeated typed occurrences, sharing normalized outputs, or treating compressed and SWA roles as interchangeable.

The report retains this numerical gate instead of calling donor dense BF16 correctness a native sparse guarantee.
