# T02 — TP4 alternative: native small-head sparse attention

Lane: **different_topology**. Live-layout priority: **not ranked**. Status: conditional plan; no GPU test or measured gain.

## Problem and causal hypothesis

With64 attention heads, TP4 has16 local heads; padding to64 wastes work. Native16-head prefill/decode can avoid that work.

## Applicability to our H200 deployment

Live TP1 has64 local heads: small-head gates do not apply. Decode eligibility also uses query rows, not client concurrency.

## Isolated control and treatment

Separate TP4 baseline: prefill #61615 plus required FlashMLA26; independently decode #59418; broader #57673 is an alternative backend, not a stacked first arm.

## Evaluation and predicted mechanism

E1: native agent-f75; E2: frozen Mooncake median/burst/cache-heavy. H200 capacity discovery and held-out confirmation in PROTOCOL.md.

Measure: Local head count, query rows, prefill/decode kernel time, temporary buffers, quality, TTFT/ITL and goodput.

## Why an additional evaluation is or is not needed

Reuse E1/E2 and low-query-row cases; add upstream attention numerical tests. Separate model/compiler/backend manifests per alternative.

## Decision and falsification

Apply [the preregistered protocol](../PROTOCOL.md). Confirm path and missing behavior before spending GPU time. Support requires correctness, predicted mechanism movement and a useful held-out SLO outcome. Reject an active, well-measured change with no useful endpoint gain or a correctness/tail regression. Mark absent-path, underpowered or failed-replay cases inapplicable/inconclusive; do not label them disproven. Correctness lanes establish only scoped correctness.

## Evidence limits

No direct live DP4 gain; dependency and head-padding absence checked in installed sources.
