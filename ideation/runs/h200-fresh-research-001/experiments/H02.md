## Model statement and experiment

Share FlashMLA decode plans across compatible KV-cache groups within one metadata-building pass, conditional on the pinned H200 runner still creating duplicate plans. The supplied patch implements per-pass holder sharing; the author reports fewer planner launches on H20 TP8, using synthetic acceptance for serving measurements. That establishes an implementation mechanism, not an H200 benefit. Unlike small-head kernels, this change does not require TP4 or TP8 and can plausibly apply to TP1. Its value depends on exposed redundant planner work under real DSpark rejection. Reuse must preserve equal live lengths, masks and replay state, rather than merely matching tensor shapes. First inspect baseline membership and builder dispatch; then compare unchanged execution with sharing alone, preserving all serving settings and measuring primary-workload latency and throughput.

**Control:** The supplied pinned H200 baseline, including existing same-type reuse, seq64, graphcap512, native rejection and enabled telemetry. This existing static implementation is the primary comparator; no cheaper equivalent flag is established by the supplied sources.

**Treatment:** First perform the source/configuration presence check. Then attest the port, verify activation and correctness, run an unprofiled screen, collect a separate mechanism diagnostic, and confirm with at least five alternating paired full-run blocks for small gains. Preserve native agent-f75 8K/1K prefixes and fixed-schedule Mooncake anchors adapted to seq64. Keep 1K/1K diagnostics separate.

**Metrics:** Activation: shared-holder uses divided by compatible group/layer-type opportunities, plus planner launches per eligible pass, separately for target/drafter and eager/graph execution on every rank. Serving: request TPOT=(last-first token time)/(server output tokens-1), excluding undefined one-token cases; TTFT tails, exact output tokens, throughput, historical-scorer goodput and replay lag. Record all-rank draft/verify/accepted deltas, KV blocks, preemption, missing coverage and resets. Measure exposed planner time only in separate diagnostics.

**Supports if:** Compatible groups demonstrably share holders, redundant launches decrease, correctness passes, and paired full-run intervals show a predeclared useful TPOT or goodput improvement without unacceptable TTFT-tail or quality regression. Check baseline drift and use full runs as statistical units.

**Rejects if:** Equivalent sharing is already active; adequately covered execution has no redundant compatible plans; reuse violates live-value invariants; or adequately powered confirmation rules out the predeclared useful serving improvement.

**Inconclusive if:** Runner dispatch, eligible opportunities or telemetry coverage are unresolved; intervals overlap both useful improvement and regression; or source-level launch removal cannot be connected to exposed execution time. Sparse or uncovered zero-hit counts are inconclusive.

**Held out condition:** Ragged arrivals, mixed prefill/decode, cold and warm prefixes, long contexts, idle DP ranks and changing speculative outcomes, using the same seq64 topology.

**Correctness:** Exercise the newly shared-cache branch explicitly. Check equal live topk_length, extra_topk_length, masks and replay state across participating groups; prevent reuse across unrelated passes. Compare eager and graph replay after changing lengths, page tables, padding and request membership. Verify plan refresh, separate target/drafter ownership, output equivalence and distributed isolation. Map these checks to applicable G01-G05 once their definitions are supplied.

**Cost:** Low relative integration effort: three Python files and no kernel rebuild indicated by the supplied patch; actual port effort remains unknown. Stop after the presence check if redundant planning is absent. With eight-GPU node price P per hour, report cost per output token as P*T/(3600*N_output); P is unknown. Exclude profiling runs from the serving frontier.

## Critique retained

- h200_applicability_and_correctness_required: The three-file Python patch provides a plausible SM90 port without requiring small TP-local head counts. Active runner dispatch and compatibility across groups remain unknown. The patch states "FlashMLA checks only shapes"; its cache key does not itself establish equal live lengths, masks or replay state. The proposed correctness checks appropriately target these unresolved invariants.
- The installed holder-construction excerpt does not establish absence of cross-group sharing at its callers.
- Sharing by configuration key is insufficient unless live-value equivalence follows from verified builder invariants.
- The H20 launch counts and synthetic-acceptance setup cannot establish TP1 launch savings or real-rejection serving gains.

**Required revision:** Retain as a deferred candidate. Before implementation, resolve runner dispatch and equivalent sharing at the pinned commits. Specify how compatibility is established without adding production device-to-host synchronization, and distinguish shared-holder uses from planner launches actually removed during graph replay. Freeze useful-effect margins, coverage requirements and stopping limits before future testing. Weighted score: 76/100; the unknown applicability gate prevents qualification.
