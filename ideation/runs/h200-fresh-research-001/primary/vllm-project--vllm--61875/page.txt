Overview
Proof of concept: on Hopper with expert parallel, run DeepSeek V4 / V4.1 MXFP4 experts on Humming with block FP8 (group 128) activations by default instead of BF16. Related to
#59488
(opt-in
--quantization-config.moe.activation
for the same method), which this would rebase onto.
Claims
DeepSeek-V4-Flash, TP4 + EP on H200: +25% decode output throughput (TPOT 25.2 -> 20.0 ms) and +6% prefill-heavy throughput, with GSM8K unchanged.
Scope:
Mxfp4MoEMethod
with the HUMMING backend, DeepSeek V4 routing (V4 and V4.1), expert parallel, SM90. Everything else keeps the current BF16 default, and
VLLM_HUMMING_INPUT_QUANT_CONFIG
still overrides.
Validation
DeepSeek-V4-Flash on 4x H200, Humming MoE backend (the SM90 default). Baseline is
main
(BF16 activations). The FP8 column was measured with
VLLM_HUMMING_INPUT_QUANT_CONFIG='{"a_dtype": "float8e4m3", "input_scale_group_size": 128}'
. That override resolves to the same Humming layer config as this PR's
kFp8Dynamic128Sym
(group 128,
DynamicGroup
, float32 scales on SM90).

Details
DeepSeek V4 MXFP4 experts go through
Mxfp4MoEMethod
, which passes no activation key. On SM90 the Humming backend then builds its input schema from
VLLM_HUMMING_INPUT_QUANT_CONFIG
and defaults to BF16. This PR sets
activation_key = kFp8Dynamic128Sym
in that case.
#59815
already plumbs the key into Humming's input schema with fallback disabled. The DeepSeek V4 checkpoint declares block FP8 GS128 with UE8M0 scales for its FP8 layers, so block FP8 matches what the model was built for.
Why only with EP: under EP each rank runs full-size experts (hidden 4096, intermediate 2048), where Humming's FP8 x MXFP4 kernels are faster. Under TP4 the intermediate is split to 512 per rank, and dynamic activation quantization costs more than it saves. Gating on DeepSeek V4 routing keeps other MXFP4 models (Kimi K3, plain mxfp4) unchanged.
Limitations:
DeepSeek-V4.1-Flash was not run; it shares the routing and method, so it gets the same default.
[Perf][DeepSeek V4.1] Humming indexed MoE GEMM with EP on Hopper, and a named MoE activation format
#59488
reports the indexed GEMM is faster for V4.1 with EP on Hopper, and the FP8 gain should be re-measured on that path.
Measured on H200 with the default all2all backend. DeepEP v2 and H100/H20 were not measured.
The FP8 column was measured with the equivalent env override. I could not rerun end to end on this exact build because the shared machine's GPUs were taken.
Not a duplicate:
[Perf][DeepSeek V4.1] Humming indexed MoE GEMM with EP on Hopper, and a named MoE activation format
#59488
adds an opt-in activation format for the same method, and this PR changes the default for one configuration.
[Perf][Humming] Integrate fused SwiGLU FP8 quantization for W2
#53184
fuses SwiGLU with per-token FP8 quantization for W2.
[Model][Quant] DeepSeek-V4: opt-in lossless MXFP4->block-FP8 expert dequant (Hopper prefill speedup)
#53709
dequantizes experts to block FP8 instead.
