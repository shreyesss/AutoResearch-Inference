# H09 — Shared prefix affinity at final DP rank

Research priority: 9. Root disposition: **defer implementation; retain conditional design**. Frozen-policy selection: **deferred**, score **76.0/100**. Scores are judgments, not speedups.

Original proposal: `h200-systems-003`. Latest immutable identity: `hypothesis:249a1e71e106968863d7f30c3f355944a2b4d5fd54a03e474186017e9b877b0b`.

## Source observation

PRs #59468/#52464/#51199 and CacheRoute expose cache locality and worker-local routing issues. Two API workers per replica mean endpoint affinity need not imply final-rank affinity.

## Upstream fix

Existing upstream tie-break/locality mechanisms inform a shared per-replica affinity table at the final rank decision; this shared adaptation is a root hypothesis.

## Root transfer prediction (untested)

Stable prefix placement may reduce duplicate prefill, but stale placement and hot-prefix imbalance may cost more than they save.

## Baseline eligibility and cheapest first step

Inspect existing router and rank-selection behavior, prefix key/salt semantics and shared-state lifetime before implementation.

## Strongest comparator

Current routing, least-loaded routing and a simple fixed hash at equal load; optimize only if baseline already fails to exploit useful locality.

## Activation denominator

Affinity-eligible requests, decisions honored at final rank, cache-hit source, stale entries and bypass rate across both API workers.

## Mechanism and competing explanation

Avoided prefill tokens versus queue imbalance, lookup/locking overhead and routing-to-rank mismatch.

## Reject, stop or defer

Current routing already provides equivalent locality, all hits occur upstream, or hotspot/tail regressions outweigh saved compute.

## Correctness scope

Tenant/cache isolation, stale state, cancellation, restarts, concurrent API workers and G04/G05 semantics.

## Workload and held-out conditions

Prefix-heavy E1 and cache-heavy E2 plus cold/unique-prefix negative controls.

## Decision rules and cost

Keep applicability, activation, correctness, mechanism, service value and integration verdicts separate. Missing telemetry or intervals wider than the decision margin are inconclusive; an inactive branch is not a disproved algorithm. Freeze adequate exposure and correctness tolerances before GPU work. ## Model statement and experiment

Test prefix affinity at the final DP-rank decision, with affinity information shared across the two API workers within each replica. First inspect existing routing and join requests to replica, API worker and final rank; endpoint affinity alone cannot establish reusable KV locality. Narrow the earlier queue-skew proposal to preferring a remembered compatible destination only among equally loaded ranks, preserving lower-load decisions. Compare shared state with both the existing process-local tie-break proposal and a stateless deterministic tie-break. The expected benefit is avoided prefill for retained exact prefixes. Reported throughput regressions and fragmented API-local maps make cache-hit improvement insufficient evidence; useful selection requires better serving results without unacceptable queue concentration.

**Control:** Attested load-aware routing with prefix caching ON and unchanged external routing. Compare current behavior, PR #52464-style local hints and deterministic prefix hashing among tied ranks before qualifying shared state.

**Correctness:** Preserve exact cache validation rather than trusting routing hints. Test cache_salt and LoRA isolation, block boundaries, stale entries, bounded eviction, explicit-rank bypass, fairness for unrelated ties, cancellation and concurrent updates. Validate outputs and tool-call behavior on a quality subset; map cache/distributed checks to G01-G05 once defined.

**Cost:** Moderate routing integration cost; inexpensive source and trace falsification first. Shared-map overhead must be charged to the treatment. Use unknown node price C8 and measured qualified tokens for parameterized cost.

**Held out condition:** Primary native agent-f75 8K/1K prefixes and fixed Mooncake anchors. Hold out hot-key skew, changed retrieval prefixes, eviction pressure, connection churn across API2 and cold/warm transitions. Cache-isolated 1K/1K is a separate negative control.

**Inconclusive if:** Request-to-final-rank joins or residency evidence are missing, warmup differs, tied opportunities are insufficient, or intervals cannot distinguish cache benefit from run variation.

**Metrics:** Denominator: tied routing opportunities for repeated compatible prefixes of at least block64; separately count the subset with observed retained reusable KV. Numerator: shared-hint decisions reaching that destination. Record API-worker crossings, served cached blocks, avoided prefill tokens, table overhead, rank queue distributions, KV evictions/preemptions, TTFT tails, request TPOT, exact tokens, qualified goodput and replay lag across both replicas.

**Rejects if:** Equivalent final-rank affinity is already active; adequate coverage finds negligible recoverable work; stateless/local comparators match the result; or higher hit rate accompanies worse qualified serving performance.

**Supports if:** Shared visibility recovers attributable prefill work and improves unprofiled TTFT or qualified goodput beyond both simple comparators without predeclared queue-tail or TPOT regressions. Confirm small gains with at least five alternating paired full-run blocks and held-out intervals.

**Treatment:** First inspect routing membership and collect final-destination joins. Then introduce bounded shared hints within each replica only, following activation and correctness qualification before unprofiled comparisons.

## Critique retained

- h200_applicability_and_correctness_required: A host routing adaptation is plausible on SM90, with appropriate cache isolation, stale-entry, concurrency and bypass checks. The shared-table integration, installed routing behavior and exact prefix-key semantics remain unspecified or unverified. The source's local tie-break implementation does not establish the proposed shared implementation.
- A remembered destination is neither current residency evidence nor proof that the destination remains eligible under load precedence.
- Define prefix length and matching across growing conversation turns; a common first block can concentrate unrelated requests.
- The author's variance explanation for negative results is unverified.
- The shared-state implementation is a transfer proposal, not an implementation demonstrated by the supplied PR.

**Required revision:** Weighted score: 76/100; deferred on applicability. Specify prefix-key and update semantics, shared-state synchronization and failure fallback, and the eligible-resident-tied opportunity denominator. Label source throughput as per-user output token rate and retain both simple comparators.
