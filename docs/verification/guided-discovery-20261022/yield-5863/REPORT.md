## 4. Executed bounded action: CF59 main-lane scratch-user admission

### Question

Can a conservative **CPU-known per-step predicate** exclude additional library users between the first target LM head and the intended side-stream join, narrowing CF59's unproven scratch conflict? This is useful before asking for new traces or writing a stream adapter.

The first target logits GEMM is inside `GPUModelRunner.sample` before rejection sampling. `sample_tokens` can perform two more prompt-scoring routes before constructing AsyncOutput. Existing root review correctly identified that “fork after the first head” alone is insufficient. This audit follows the actual guarded branches and the sampler host wrapper.

### Source results

1. `Sampler.apply_sampling_params` returns the identical logits tensor when **no active request has needs_logits_processing**. The flag aggregates sampling parameters, thinking-budget state and every native/custom logits processor at add_request. Checking only temperature1/top_p1 is weaker and is insufficient.
2. `PromptLogprobsWorker.compute_prompt_logprobs` checks selected CPU request flags before any scoring call. The fixed-ID scorer checks `token_id_scores` before its callback. A conservatively empty fixed-ID table is a sufficient guard; it may unnecessarily exclude other inactive requests, which is acceptable for initial admission, not a coverage estimate.
3. Under the ordinary RejectionSampler path with actual draft rows, its host wrapper gathers IDs/positions, invokes parameter application, allocates local statistics/output tensors and launches named Triton rejection/resampling kernels. The inspected `rejection_sample` host function contains no GEMM or workspace-manager call. This does **not** certify every custom/native callee or PyTorch allocator behavior.
4. The context's two inspected MXFP8 linear wrappers invoke activation quantization and `vllm_flashinfer.mm_mxfp8`. The vLLM custom op delegates to external FlashInfer with `out=None` and **no caller-supplied scratch argument**. The vLLM workspace-lane abstraction therefore does not itself establish ownership of any external FlashInfer scratch. Selected external version/backend, internal storage and current-stream behavior still need proof.
5. `use_workspace_lane` is a Python ContextVar, not an automatic CUDA-stream namespace. A side-stream adapter must deliberately use the intended lane and respect its warmup/lock contract. External code that does not consult that manager is not isolated merely by selecting a lane.

Relevant exact sources are copied and hash-pinned in `source-manifest.json`, backed by byte equality to the retained c455 git archive. See `sampler.py:226`, `prompt_logprob.py:69/120`, `rejection_sampler.py:250/407`, `rejection_sampler_utils.py:1030`, `linear-flashinfer.py:96/188`, `flashinfer.py:1054`, `workspace.py:35/121` and `model_runner.py:1604/2106`.

### Actual CPU execution

`source_gate_probe.py` extracts the unchanged three methods from source with postponed annotations, then invokes only their CPU control branches. It imports no vLLM, torch, NumPy or GPU library. A tiny indexing stand-in supplies CPU boolean metadata; negative controls trap allocation or the next attribute access.

- all-false processing flags: identical input object returned, no allocation/processor call;
- mixed true flags: reaches allocation trap, so fast-path admission must fail;
- all-false ordinary prompt-score flags: empty result before logits callback;
- mixed true: exits the first guard and reaches the explicit trap, **not** a successful scoring execution;
- empty fixed-ID table: empty result before logits callback.

A source AST inventory records direct call sites in the complete rejection_sample host function. This is a bounded source-control check, not numerical inference, actual allocation, stream, capture or native-scratch validation.

### What decision changed

CF59 need not treat arbitrary logits processors and optional prompt heads as unbounded unknowns in its first arm. An explicit conservative predicate can require the standard rejection path, draft rows, all-false processing flags, no output/prompt score requests, no watermark/sampling-mask/grammar/custom sampler or connector side effect, and the already-required graph/row/ownership conditions. Keep original early AsyncOutput before join and forbid overlapping next-step/context-buffer reuse.

This makes a smaller backend-specific investigation possible. It does **not** establish that current agent-p75/Mooncake steps satisfy every guard, or that this is the only safe predicate. Existing saved temp1/top_p1 request settings do not prove the computed needs-processing flag or absence of every optional runtime path. No runtime eligibility frequency or saved milliseconds is inferred.

Before implementation qualification, still inspect the actual installed FlashInfer revision's quantizer/GEMM scratch and stream behavior, PyTorch cross-stream tensor lifetime/recording, and generation-owned staging. The available retained source wrapper cannot close those external internals. No additional network search was made simply to choose an arbitrary newer dependency. This is a **CF59 refinement, zero new hypothesis**, and remains deferred.
