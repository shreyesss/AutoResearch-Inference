# H02 — Byte-preserving compaction diagnostic

**Decision.** Consider one CPU-first experiment: replay a conservative, byte-preserving KV page-compaction design against the existing allocator. Do not reopen the prior four-bit quantization proposal. Unchanged aggregate accuracy does not establish exact greedy-token equivalence, and calibrated clipping plus an FP16 residual window does not restore information discarded by quantization [H02-E1, H02-E3]. No new evidence resolves that rejection.

**Adapted mechanism.** Isolate CACHE-Q's independent page manager: move live cache data without changing bytes and update logical-to-physical indirection [H02-E2]. The hypothesis is that reclaimable fragmentation remains despite current paging, and safe compaction can return physical pages while preserving every logical KV value and its interpretation. This is a distinct component adaptation, not a renamed quantization proposal. Its benefit is unknown: the reported 35% combines quantization and compaction and cannot be assigned to page management [H02-E2].

**Activation and strongest objections.** Current paging may already reclaim all relevant capacity; free slots or bytes do not necessarily translate into returnable physical pages. Relocation additionally conflicts with active graph pointer reuse and concurrent readers [H02-E3]. A design must relocate only at verified quiescent boundaries, update every indirection and graph reference before reuse, and prevent reclamation while any reader can access the old location. If graph references cannot safely be refreshed, restrict the eligible pages or defer compaction. Pauses, graph rebuilding and extra metadata may erase practical value.

**Proposed CPU experiment.** Pin the saved allocator trace and current allocation semantics. Use allocated page IDs, live token counts, free-list events and graph pointer reuse to calculate the present peak/reserved allocation and a conditional upper bound on pages compaction could release. Distinguish live payload, reusable allocator capacity and memory actually returnable to the device. Replay candidate moves with symbolic byte identities using the existing ownership/byte-preserving-move evaluator [H02-E3, H02-E4]. Check that logical token ownership and offsets remain unchanged, moves do not overlap unsafely, every live reference resolves correctly, and pages are reclaimed only after readers and graph references are retired. Mark synchronization details absent from the trace as unknown rather than assuming quiescence.

**Result branches.** Stop if existing allocation already achieves the same releasable-page count, or no pages can move safely under the current execution contract. Advance design only if the trace identifies recoverable pages and an implementable quiescence/reference-update protocol. Return inconclusive if missing reader lifetimes or graph semantics determine safety or reclaimability; the cheapest next step is to obtain those source/trace facts. No fixed savings threshold is invented.

**Proof versus testing.** CPU reasoning can establish conditional mapping/ownership invariants and byte preservation for an explicitly modeled move algorithm; trace replay tests those properties on the supplied events. The trace contains no KV tensor values and cannot demonstrate actual runtime tensor equality or attention numerics [H02-E3, H02-E4]. A later implementation needs a semantic argument that identical logical KV bytes reach the same attention computation in the same order, with no races, stale graph pointers or address-dependent dispatch changes. Token-equality tests are necessary regression checks but finite success is not a universal proof [H02-E4]. Keep the exact-equivalence requirement intact.

**Later matched measurement.** Once correctness is justified, compare current paging with the complete safe compaction implementation on matched model, long-context workload and runtime. Measure actual peak/reserved device KV memory, returned pages, relocation overhead, pauses and latency; record graph/synchronization costs. No savings or speedup follows from this CPU diagnostic alone. Self-review verdict: advance bounded diagnosis, defer implementation/performance qualification. All conclusions use the four supplied fixture records; no execution or external retrieval occurred.
