# H15 — Bound draft attention only after context-dependent acceptance loss

Lane: **main**. Live-layout priority: **15**. Status: conditional plan; no GPU test or measured gain.

## Problem and causal hypothesis

At long contexts, an unsuitable drafter context may increase draft time or reduce accepted tokens. A bounded draft window could improve useful tokens per engine step.

## Applicability to our H200 deployment

Measure acceptance versus context while controlling cache-hit/restoration and workload domain. Inspect drafter training context and RoPE. Stop if no degradation or draft bottleneck.

## Isolated control and treatment

A: fixed k5/full draft context. B: bounded draft_context_window selected on discovery data; keep adaptive verification off.

## Evaluation and predicted mechanism

E1: native agent-f75; E2: frozen Mooncake median/burst/cache-heavy. H200 capacity discovery and held-out confirmation in PROTOCOL.md.

Measure: Acceptance by position/context, draft time, accepted tokens/step, ITL, real-text quality and goodput.

## Why an additional evaluation is or is not needed

Reuse existing long-context/session and Mooncake cohorts; add lengths through existing client only when missing. SPEEDBench/SpecBench supplies domain coverage if current synthetic/trace texts cannot represent draft acceptance.

## Decision and falsification

Apply [the preregistered protocol](../PROTOCOL.md). Confirm path and missing behavior before spending GPU time. Support requires correctness, predicted mechanism movement and a useful held-out SLO outcome. Reject an active, well-measured change with no useful endpoint gain or a correctness/tail regression. Mark absent-path, underpowered or failed-replay cases inapplicable/inconclusive; do not label them disproven. Correctness lanes establish only scoped correctness.

## Evidence limits

Kimi evidence does not establish DeepSeek gain. Short8K E1 likely misses the target mechanism.
