# Lessons that change the next experiment

These are evidence-backed process decisions, not a replacement for historical verdicts. Updated 2026-10-21 (Asia/Calcutta).

| Lesson | What happened | Rule for subsequent work |
| --- | --- | --- |
| A real inefficiency is not necessarily an expensive bottleneck. | C03 changed the intended graph selection, but selection never measured how much exposed time the occasional smaller draft graph could save. | Before spending a full attempt, identify the affected work, measure its exposed contribution, and show a plausible saving after overhead. Event count, row count and reviewer score do not substitute for time. |
| Selection needs an explicit benefit, cost and pilot rubric. | Removing novelty as a default veto did not supply a measured ROI gate; C03 advanced from activation to a service attempt with the time contribution unknown. | Record expected optimization delta, engineering hours, GPU-hours and uncertainty. Use a bounded pilot with prospective promotion/stop criteria; compare predicted versus actual gains and costs. Follow the [ROI rubric](../docs/HYPOTHESIS_ROI.md). |
| Acquisition depth must be reported separately from research completion. | The fresh cross-repository pass indexed 5,532 URL/title entries and retained 108 selected primary pages and 69 patches; this was not an exhaustive archive. | Report URL indexing, opening records, discussions and patches separately, with per-feed completion evidence. See the [collection audit](../docs/CORPUS_AUDIT_2026-10-21.md). |
| Do not invent the cause of a disappointing result. | C03's service screen worsened long ITL and TTFT; no component timing establishes the cause. Kernel tiling, collectives, CPU work and scheduling are possibilities. | Separate observations, source-supported mechanisms and causal conjectures. Keep the regression unexplained until an experiment discriminates the causes. |
| Use the correct denominator. | Warmup-inclusive diagnostic histograms differ from strict profiling events; DP ranks participate in one event. | Label phase, cohort and rank aggregation. Do not multiply correlated ranks into a larger sample or turn graph-capacity changes into FLOPs/time claims. |
| Keep a valid unfavorable screen. | One fresh paired screen met the scoped gates and failed its promotion rule. | Preserve the frozen stop. Do not retry for a favorable seed or explain away cache/acceptance differences as external noise. One screen is also not a precise universal effect estimate. |
| Distinguish complete, valid, eligible and statistically conclusive. | C03 exports completed, but both arms missed service SLO eligibility; one valid AB seed did not establish a confidence interval. | State each property separately and retain errors and failed diagnostic attempts. |
| Check source-level constraints precisely. | A trained/default proposal width was initially interpreted too strongly as a hard k3 restriction. | Cite the actual guard and model path. A configuration default is not an assertion, and a Qwen guard is not a DeepSeek constraint. Correct the research record when evidence changes. |
| Design a diagnostic whose observables can answer its decision. | The initial timing gate demanded a cross-rank critical path that the minimal profiler labels could not establish. This was corrected before traffic. | Use this trace for conditional occupied-time materiality; retain exposed service time as unknown. Do not force a causal claim from insufficient instrumentation. |
| Attest installed files, not just a version string. | One of14 checked source files in the pinned image differs from the nominal upstream commit. | Preserve the actual image as the control and record exact differences before borrowing upstream assumptions. |
| Keep evaluator independence. | C03 used separate evaluator designer, evaluator tooling builder and optimization developer. | Continue that separation. The root orchestrator launches workloads, preserves the original environment and publishes evidence. |
| Validate actual profiler schema and decode-cycle coverage. | The k5 diagnostic emitted mirrored CPU/GPU annotation names; a separately reviewed offline filter fixed that reader error. One cell still had only4 complete decode cycles, and five had invalid GPU/launch timing associations. | Preserve the original reader failure. Test actual schema distinctions and require native cycle joins;20 profiler steps do not guarantee20 decode samples. Keep inadequate timing inconclusive and require a prospective addendum before another capture. |
| Target ownership does not prove removable target computation. | Target-owned GPU intervals included NCCL activity; uneven recording/export could perturb cooperating ranks, and one inactive bracket overlapped export. | Report collective/waiting uncertainty, contaminated brackets and idle/overlap separately. Do not translate target busy fraction into expected AV savings. |
| Budget cold startup and evidence processing. | The short986-request diagnostic occupied eight H200s for about38.6minutes including startup and cleanup; arrival replay itself was about5minutes. | Quote total node/GPU allocation cost alongside capture duration. A diagnostic that preserves full experiment attempts still consumes real resources. |
| Preserve evidence where the reader can recover it. | Detailed logs and evaluator sources spanned two local worktrees and were not yet upstream. | Push readable records plus compressed, checksummed evidence and a restoration map. Retain sealed byte contents and original paths; organize through indexes. |
