Motivation
PR
#41364
adds
topk_page_transform
, which combines DeepSelect Top-K selection with the page-table transform in its epilogue.
DeepSeek V4.1 on Hopper still uses:
torch.topk
  -> sort raw indices
  -> gather physical KV slots
This PR connects the new DeepSelect operator to that runtime path.
Modifications
Use
topk_page_transform
for the SM90 full-topk decode path.
Write transformed int32 KV slots directly into the existing output buffer.
Preserve raw-index ordering with
sorted_index=True
.
Keep the existing Torch path when raw indices are also required.
Keep SM100 and newer architectures on the existing DeepGEMM path.
Add CPU dispatch/fallback tests and an H20 runtime integration test.

The replaced region was benchmarked on NVIDIA H20 with CUDA 13.0 and PyTorch 2.13. Each complete run used 20 warmup iterations followed by 5 groups of 100 measurements. The table reports the mean of the medians from two complete runs.

b49e63d
Review flagged test_constructor_enables_deep_select_only_without_deep_gemm
and test_decode_uses_fused_page_transform as testing no real functionality:

restate the _torch_decode call site; the constructor test mirrors the
one-line gating expression. Real coverage runs the kernel through the same
call site against a torch.topk reference in

(test_page_transform_matches_reference, test_full_topk_decode_runtime_integration).

…
3bb8cc1
Review flagged test_full_topk_decode_runtime_integration with the same
rationale as the CPU wiring tests: it hand-assembles FullTopKIndexer via
object.__new__ and stubs decode_scores, so beyond the direct kernel tests
