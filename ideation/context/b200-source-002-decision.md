# Decision — six new B200 inference-serving ideas

Research completed 2026-10-19 (Asia/Kolkata). This is a **ranked experiment-selection shortlist**, not a report of new measured gains or approval to patch/build/run GPUs. The imported `LAT-2XDEP4-R7b` c384 point is 27.6882 req/s, request TPOT p50/p99 12.850/19.329 ms, TTFT p99 2.180 s and reported cache-hit share 0.7736 on one eight-B200 node; it is one aggregate discovery run without a kernel, rank or request trace. Exact source/config/hardware limits are in [brief](brief.md). Each card's first serving point uses a contemporaneous unchanged R7b control and same request bodies, cache preparation, eight-GPU budget and load mode; candidate changes are recorded. A 120 s warmup + 150 s scored point per arm gives **1.2 GPU-hours of scheduled traffic for two arms**, excluding setup/build/startup/drain and any repeats. That is a planning baseline, not a required sample floor.

The order favors cheap discriminating checks and the active node's likely operating range. It is conditional: evidence of no rank skew would remove H04/H02, no avoidable repeated-prefix misses would remove H05, and a strict bit-identical output contract would remove H01. H03's published crossover makes its fixed backend a component question before service promotion. No numeric R7b speedup is forecast.

## Exploration coverage and alternatives

| Direction | Selected or reason not selected |
| --- | --- |
| V4.1 replay / graph integration | **H01 selected**; separate from prior batch's H01 decode candidate-selection port, which stays prior work and is **not counted**. |
| EP prefill/decode scheduling | **H04 selected.** Active-demand long-prefill chunk cap (S2 in [schedule note](notes/schedule_spec.md)) is a distinct cheap fallback if a parent trace shows long mixed steps without rank skew; it lost a slot to broader mechanisms because current vLLM already chunks/priors decodes and R7b miss-step evidence is absent. |
| Speculation | **H06 selected** for draft-work adaptation. Adaptive **verification** activation (S3) lost to [issue #59970](https://github.com/vllm-project/vllm/issues/59970)'s backend-specific graph crash and weak safe-mode gain; MegaAttention compatibility remains a future question. Prior #59468 slot fix is unlikely to bind R7b's 16K budget. |
| Prefix KV / routing | **H05 selected.** One-use KV probationary eviction is distinct but lower readiness; R7b has no hot-prefix eviction evidence and hybrid-cache correctness is costly. Generic waiting-queue affinity had a near-zero correct async result in [RFC #42185](https://github.com/vllm-project/vllm/issues/42185). CPU/SSD KV offload needs a larger working-set case and DSV4 layout fixes. |
| MoE and Engram | **H02/H03 selected.** Direct DeepEP dispatch is inactive on the measured DeepGEMM MegaMoE path. Private-THP Engram #59923 had weak comparable small-row DEP4 effects; B200 Engram threshold adaptation remains a profile-gated alternative. Native W4A4 port overlaps H03's precision/backend question. |
| Prefill/decode disaggregation | [RFC #57383](https://github.com/vllm-project/vllm/issues/57383) is design-only and would change topology, weight residency and transport; lower readiness/cost-effectiveness for this one-node batch than H01 replay activation. |
