# Q04 — Qualify actual tool-turn encoding and streamed arguments

Lane: **correctness_gate**. Live-layout priority: **not ranked**. Status: conditional plan; no GPU test or measured gain.

## Problem and causal hypothesis

Incorrect tool-turn boundaries or truncated DSML streaming can produce invalid model inputs/outputs while token throughput remains plausible.

## Applicability to our H200 deployment

Observed parser is deepseek_v41; checkpoint revision is pinned. Decide intentional encoding-version migration explicitly rather than silently changing workload tokens.

## Isolated control and treatment

Golden tool conversations versus the intended checkpoint encoding; separate parser fixtures for truncated/closed streamed arguments, one patch at a time.

## Evaluation and predicted mechanism

E1: native agent-f75; E2: frozen Mooncake median/burst/cache-heavy. H200 capacity discovery and held-out confirmation in PROTOCOL.md.

Measure: Exact encoded token IDs, reference reasoning retention, JSON validity and streaming assembly.

## Why an additional evaluation is or is not needed

Synthetic and Mooncake text traces are not tool-role correctness suites. Reuse upstream golden fixtures; a new performance harness is unnecessary.

## Decision and falsification

Apply [the preregistered protocol](../PROTOCOL.md). Confirm path and missing behavior before spending GPU time. Support requires correctness, predicted mechanism movement and a useful held-out SLO outcome. Reject an active, well-measured change with no useful endpoint gain or a correctness/tail regression. Mark absent-path, underpowered or failed-replay cases inapplicable/inconclusive; do not label them disproven. Correctness lanes establish only scoped correctness.

## Evidence limits

Freeze any qualified encoder change in common A/B baseline because it changes input lengths.
