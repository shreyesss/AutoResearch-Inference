Exact logs remain alongside this report.

1. [SpecEdge, October6](https://zenodo.org/records/23186563) motivated the precision/acceptance tradeoff, but its main table combines **quantized target** with a small sequential draft. Target quantization violates this experiment's frozen target contract; stopping that sequential draft early does not save DSpark's already-computed parallel backbone/head rows. The paper does not establish our candidate's speedup. It omits an exact accelerator and visible artifact URL despite an artifact claim; table significance compares AR against EG-Spec, whereas the abstract claims significance against static speculation. Five trials are stated, but the paired test's observation unit is not specified. Those are reproducibility gaps, not proof of fabrication.
2. [HyCo, October15](https://arxiv.org/abs/2610.21436) contains both exact and relaxed verification. Its main W4 native head uses QAT, so that treatment is excluded from the no-training scope. **The W8 post-training diagnostic is separable**: the paper reports 98.8% agreement on its own validation set without training. This establishes neither our acceptance nor our runtime. Its restricted draft output vocabulary is another separable exact-verification component, but is a larger intervention with keep-set construction and support accounting; do not bundle it into the precision arm. Its mobile NPU/cloud topology, Gemma models and 1K context do not transfer to native DSpark SW128. Relaxed epsilon acceptance is excluded; exact verification remains relevant.

Other eight records: Adaptive Hybrid Quantization abstract-only/generic edge-cloud; Shortcuts Safety has no abstract; ASD regret-budget verification changes exactness (diagnostics only); SFAD involves DPO/target steering; diffusion trajectory work has a different generation model; software-engineering study helps workload selection but is April-origin; online draft co-training requires training and PP/CP assumptions absent here; SpecStream depends on offloaded target KV and overlaps prior asynchronous scheduling families. None is counted as independent confirmation of an actual target gain.

## Concrete implementation gap, and what is already there

The pinned code already implements `quantized_lm_head_copy` with FP8 and NVFP4 formats, preserving the original target head and maintaining derived-copy reload utilities. EAGLE/MTP's loader calls it. `SpeculativeConfig` expressly rejects `draft_lm_head_quantization` for DSpark, and DSpark's loader assigns the original target head directly. Thus **this is a DSpark integration hypothesis using existing code**, not a newly invented quantization kernel or an existing DSpark CLI toggle.

Candidate **QH45**: extend that isolated derived-head facility to the eligible native DSpark loader, beginning with FP8, while keeping target weights/head, DSpark backbone, Markov bias, sampler and verification policy unchanged. Treat NVFP4 as a separately evaluated arm only after backend eligibility; do not apply quantization to the shared target object. No neural-weight optimization is proposed; even representation derivation has not been executed.

`DSparkSpeculator._sample_sequential` computes base logits for all `R*5` rows, adds parent-conditioned Markov bias, then samples and caches those resulting logits. Verification must consume **that actual modified proposal**, including identical temperature/support handling. Reusing old unquantized proposal probabilities would invalidate rejection sampling. Source confirms a data path; it does not prove native block-verifier correctness after a patch. Top-k drafting, greedy selection, probabilistic selection, graph capture, reload, and confidence scheduling each require their own compatibility check.

Seven AST/text checks and an exact-rational two-token single-step diagnostic ran. The latter returns target `[3/5,2/5]` with actual/cached q agreeing; using stale q instead yields `[1/5,4/5]`. This is an explicit negative control for proposal consistency, **not a test of the native five-step block sampler**. Source copies/URLs/hashes and arithmetic are in `cpu-contract-results.json`.

## Cost and ROI: no invented estimate

For the intended full TP1 head, `129280 * 5120 = 661,913,600` weights. Original BF16 storage is1,323,827,200bytes. It remains resident for target verification. A separate FP8 copy adds661,913,600weight bytes plus517,120bytes for FP32 row scales; a logical NVFP4 copy adds330,956,800packed bytes plus41,369,600block-scale bytes and a global scalar. Padding/repacking/workspaces/transient conversion and actual backend scale layout must still be checked. These are capacity counts, **not measured HBM traffic or time saved**, and apply independently to each TP1 rank.

Let `G` be expected committed tokens/round and `T` full exposed round duration. A win requires `G_new/G_old > T_new/T_old`. If the *whole round* became2% faster, losing2% or more committed progress would erase the gain; this is a conditional boundary, not an estimated2% saving. Saving half the head's arithmetic does not imply saving half the round. Added residency can reduce KV capacity or worsen admission even when a low-concurrency head microbenchmark improves.

Missing inputs: actual head's exposed fraction, active quant kernel and5R row distribution, draft-logit/acceptance drift, native block-rejection correctness, graph/reload behavior, free-memory/KV effect, adaptive verifier response. **ROI is unknown.** Paper-reported acceptance rates are not substituted for these.

## Experiment design, staged without execution

1. **CPU/source gate now:** audit DSpark loader/config, derived-copy lifecycle, numerical dtype/shape/scale requirements and complete proposal-cache path. Confirm no equivalent local DSpark patch exists. Reject an unguarded shared-object mutation. Inspect exact kernel support from source; no native import needed.
2. **Future authorized correctness gate:** pin image/checkpoint/backend and run isolated draft-head FP8 parity/error diagnostics, then native greedy equality and probabilistic/block-verification tests with actual cached q. Greedy draft choices may change while committed target greedy tokens must match. Same stochastic seed is not a sufficient distributional correctness test. Verify graph replay and reload, target head unchanged, finite outputs, full vocabulary support.
3. **Future authorized economic probe:** paired BF16-head vs separate FP8-head at observed5R shapes, synchronized complete-round and per-component timing, accepted/committed tokens by depth, memory residency/peak, workload cohort and graph mode. Preserve underlying workload rather than cherry-pick easy high-acceptance requests. Early stop if measured whole-round saving cannot tolerate measured progress loss or memory pressure.
4. **Standard serving confirmation:** keep Mooncake and agent-75 as primary workloads, paired repeated workload/seed manifests and unchanged correctness/SLA policy. Primary long-output ITL with TTFT and p95/p99 tail guards, plus SLA goodput and errors. Report acceptance, head fraction, graph bucket, KV capacity/admission and adaptive budget distributions. Rebuild the controller's normal cost profile per arm; identify fixed-budget diagnostic separately from adaptive total effect. Those workloads can test service impact; only the bounded correctness/probability/head diagnostic is additional, because traffic-level latency cannot prove sampling correctness or identify head cost.

Promotion requires deployment eligibility, correctness and confidence-supported service gain at the task's chosen threshold. This report qualifies **no implementation or GPU run**. Keep QH45 deferred pending independent review and missing exposure evidence; no acceptance quota.
