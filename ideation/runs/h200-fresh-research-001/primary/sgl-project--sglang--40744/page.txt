Describe the bug
Serving
deepseek-ai/DeepSeek-V4.1-Flash
with
--speculative-algorithm DSPARK
on
2 nodes × 4 H200 (TP8 + EP8, LeaderWorkerSet, one 4-GPU pod per node over RoCE)
deterministically deadlocks during startup, right after the DSpark draft weights finish loading. Three consecutive attempts across two different images all hang at the same point with the same split stack; removing the DSPARK flags (identical everything else) starts cleanly in ~10 minutes.
The split we capture on every occurrence (py-spy dump, all 8 scheduler processes):
Node 0 schedulers (leader, TP0-3) — parked after
Load weight end ... type=DeepseekV4ForCausalLMDSpark
:
monitored_barrier (torch/distributed/distributed_c10d.py:5435)
dist_barrier_after_load (model_runner_components/load_model_utils.py:380)   # also seen :344 on dev-cu13
load_model (model_runner.py:1307)
initialize (model_runner.py:653)
Node 1 schedulers (worker, TP4-7) — parked earlier, inside the KV-pool memory probe:
all_reduce (torch/distributed/distributed_c10d.py:3252)
wrapper (torch/distributed/c10d_logger.py:83)
get_available_gpu_memory (utils/common.py:550)
_profile_available_bytes (kv_cache_configurator.py:2214)
The worker-side ranks have posted the memory-probe all-reduce and wait for the leader-side ranks, while the leader-side ranks wait at a different synchronization point (post-load barrier). The two node halves sit at mismatched collective sites permanently — GPU utilization 0%, GPU memory and logs frozen from that point on. No watchdog fires (the stall happens before the scheduler loop starts).
This looks like the same unsynchronized-decision family as
#39886
(DSpark CUDA-graph memory check not synchronized across ranks → ranks disagree on collective participation) and the runtime variant in
#33289
(multi-node TP + DSpark → per-rank divergence → unmatched collectives). Our case adds a multi-node TP8/EP8 startup reproduction with full per-node py-spy stacks.
Reproduction rate:
3/3 with DSPARK on 2 nodes (2×
dev-cu13
, 1×
dev-cu13-dsv41
); 0 failures without DSPARK — the identical non-DSPARK cell starts cleanly in ~10 min and served a full benchmark suite.
