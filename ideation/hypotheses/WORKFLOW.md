# Keeping hypothesis records

Use [README.md](README.md) as the entry point. One Markdown card per consolidated hypothesis, one row per actual execution. Raw output stays in its original run directory. This directory adds navigation and short conclusions; no new service, database, UI or log-copying step is required.

1. **When an idea is generated:** reuse an existing mechanism ID if it is the same claim; otherwise assign the next unused ID and copy [TEMPLATE.md](TEMPLATE.md). Add a row to the index. Record the exact builder run/local ID and immutable memory ID when available. Link the proposal, critique, PR/issue/paper URLs, and saved DR/research input/output. A source bundle alone is not proof a particular PR supports the claim. Identify the specific citation in the original card.
2. **Before a test:** add its unique run ID, exact hardware/runtime/profile/workload, source revision or patch, frozen plan and evaluator. Mark it planned or running. Keep evaluator design, evaluator implementation and optimization development assigned separately, as in C03; the orchestrator owns execution.
3. **After a test:** append the outcome and the few metrics that decided it. Link the final report, original score/raw exports, detailed logs, independent review and failure/triage records. Update the index's latest conclusion. Include failed, inconclusive and inactive runs; do not turn a research rejection into an empirical failure or an SLO-ineligible completed run into an incomplete run.
4. **On a revision:** keep the hypothesis ID when the claim is unchanged, add the new implementation revision and run row, and retain earlier rows. A different mechanism or materially different claim gets a new ID linked to its parent. Hardware/workload changes are separate scopes; B200 evidence is not an H200 measurement.

`README.md` is the small cross-hypothesis summary. The individual card is the human-maintained history. Run artifacts are authoritative for results. [GENERATIONS.md](GENERATIONS.md) retains the saved builder/reviewer batches, including proposals that never reached a shortlist. [SOURCE_MAP.md](SOURCE_MAP.md) preserves all original audit-card IDs and their consolidated-family mapping. These are navigation indexes; they do not change historical source cards or the existing hypothesis-memory database.

If a workflow uses the existing `hypothesis.plan_test`, `hypothesis.start_test` and `hypothesis.test_result` tools, keep their IDs on the card and follow their existing rules. Do not require another database transaction just to browse this index. The imported C03 artifact record does not claim that a new memory-database test was registered.

Use relative links for research artifacts in this checkout. Artifacts in the separate serving worktree may use absolute local paths; keep that worktree until they are archived and update the links when moving it. Do not copy large logs or rewrite sealed evidence to improve an index. Dates in these cards use Asia/Calcutta; original artifacts retain their recorded UTC timestamps.

Maintain the [execution, analysis and meta-learning buckets](../records/README.md) after substantive research discussions. The user authorized pushing important research and evidence to the AutoResearch-Inference upstream. Commit readable records and manifests, archive bulky logs with checksums (Git LFS is available), verify restoration, and push the research branch. Preserve original sealed bytes; do not silently omit failed runs or replace the main serving environment.
