Motivation

The SM90 FP4 decode/target-verify indexer uses a capacity-sized CUDA Graph grid while visible lengths change on device between replays. For a short live context, masking K loads still leaves FP4 dequantization and dot products running on entirely invisible tiles. For example, a row with 8,192 visible positions can reserve 1,048,896 output columns.

This change skips scoring for fully invisible tiles and writes -inf directly, reducing unnecessary work while preserving the dense logits interface.

Modifications

  • Add a tile-uniform branch using the current device-side visible length. Invisible tiles write -inf on every replay, including when previously visible tiles become invisible.
  • Preserve the original arithmetic, BF16 rounding points and masks for visible and partially visible tiles. The launch grid, output shape, cache layout and candidate-selection behavior remain unchanged.
  • Add focused decode correctness and CUDA Graph replay tests to the existing FP4 indexer test file.

The change adds no host-side length read, synchronization, extra kernel launch, dependency or configuration flag. The PR changes only the kernel and its test file.

Accuracy Tests

Validation hardware/software: NVIDIA H20-3e, PyTorch 2.11.0+cu129, Triton 3.6.0.

  • Existing FP4 indexer suite with the added tests: 23 passed, 36 skipped. The skipped cases target Blackwell vectorized prefill.
  • 11 added decode cases cover empty/partial/full tiles; zero, negative and over-capacity lengths; heads 32/64; page sizes 64/128; strided inputs; padded page strides; and invalid inactive slot IDs.
  • An independent Torch FP64 reference checks FP4 decoding and the prescribed BF16 rounding points using controlled dyadic inputs. CUDA Graph replays grow/shrink visibility, change queries and slot mappings, and poison output buffers to detect unwritten tails.
  • Local compute-sanitizer memcheck: 11 cases, zero errors, with the reference calculation moved to CPU in the validation harness.
  • Separate random-input A/B checks across ten shapes are bitwise identical to the baseline.
python -m pytest test/registered/kernels/ops/attention/test_fp4_indexer.py -q -rs

Speed Tests and Profiling

All measurements below were collected on September 20 against baseline 0024efa0de38794ee309ba10ab00ebb891a3d050. The submitted commit 2e7e69b87c is rebased onto 42875bcd2a7f2d9685eb3dd98fd787b54e3787d1; the kernel and test files remain byte-identical to the validated versions. GPU tests and end-to-end measurements have not been rerun after that rebase.

End-to-end measurements

8 × H20-3e, DeepSeek-V4.1-Flash, dsv4 attention, W4A16 MoE, DSPARK, FP8 KV cache, radix cache disabled, and CUDA Graph enabled with maximum decode batch size 64. Each backend is compared against its own baseline using identical launch arguments within the pair.

The FlashInfer pair uses TP8/EP8 and max_running_requests=64. The Humming pair uses TP8/EP1. The FlashInfer configuration validates the backend on H20 with DSPARK; it is not a literal reproduction of the H200 cookbook recipe.

Both pairs use CC1, the same seed-42 token-ID request, 8,192 input / 500 output tokens, temperature 0 and ignore_eos=true. Reported values are arithmetic means of three unprofiled requests after one warmup. Profiling requests are measured separately.

TPOT decreases 55.1% with FlashInfer and 55.7% with Humming on this workload. TPOT is (last SSE time - first SSE time) / 499; speculative outputs arrive in bursts, so it is not the interval between bursts. Output throughput is 500 / request elapsed time; total throughput is (8192 + 500) / request elapsed time. These CC1 measurements do not establish peak-load capacity or gains across all lengths and concurrencies. The small sample count also limits conclusions about smaller differences such as TTFT.

Kernel microbenchmark and tradeoff

Local CUDA Graph wrapper timings use seven alternating 100 ms timing repetitions; values below are medians. K pages are independent and physically permuted. These are steady-state/warm-cache measurements; a TP8 server was idle but resident. The benchmark harness is retained locally and is not included in this PR.

Rows / heads Capacity / visible positions Baseline (µs) Patched (µs)
6 / 32 8192 / 8192 37.993 37.634

The short-prefix case improves 43.9×, while the fully visible long-sequence cases regress approximately 4.6–5.4%. The optimization retains the full grid and dense output writes, and its benefit depends on the gap between reserved capacity and live visibility.
