## Selective paper component and rejected transfers

AppendixA.4 represents each token by an independent exponential clock. For B samples per context it constructs B arrivals for every supported token and selects the B earliest. Its stated cost is K×B exponential variables plus top-B. **B is the number of samples at one context, not DSpark's five lookahead positions.** Its small-support experiments process target and draft distributions with top-k. Cropping the target support would change this experiment's law; with full support the categorical scan remains. Its older proposal-scanning implementation can be slow when the likelihood-ratio lower bound is tiny. Neither version establishes free vocabulary skipping.

For B=1, shared exponential races are equivalent in ideal arithmetic to shared Gumbel-max. At each proposed prefix, sample a target token with the same keyed noise as the corresponding draft. Commit the target token; continue down the chain only while it matches the proposal; on first mismatch end the round, or emit the bonus after a fully matched admitted prefix. This requires no target tree for B=1. The paper's multi-draft tree, watermark mechanism, top-k target change and measured Qwen2.5/corpus results are excluded. Its own limitation notes substantial coupling/watermark bookkeeping.

The paper proves an autoregressive target law with independent context-indexed clocks. The adapter below uses a persistent position tape to survive adaptive admission/retries; its justification is stated separately rather than attributed as an implemented paper result.

## Persistent-tape contract and target-only oracle

Define a fixed noise vector `G_t[v]` for each request incarnation and absolute output position t. It is regenerated by a stable effective request seed, position and vocabulary coordinate, with a declared domain; its identity must not depend on current batch row, round anchor, proposal step or number of retries. Preserve explicit-seed semantics. Request incarnation owns the state; do not substitute a reused request-slot index or silently generate a new effective seed during restore.

Define the target-only functional oracle recursively:

`Y_t = argmax_v(processed_target_logits(Y_<t)[v] + G_t[v])`.

Temperature and all supported target processing remain exactly as in the admitted reference. In ideal arithmetic, independent Gumbels give the target categorical marginal. For actual finite PRF, floating reduction and ties, the stronger practical comparison is against the exact declared target-only implementation using the same tape, not an assertion that MurmurHash outputs prove continuous independent randomness.

At a speculative round, target logits are evaluated at draft-proposed contexts. Inductively, while each previous proposal matches its oracle token, the next evaluated context is the actual committed prefix. Its target sample is therefore the oracle token. A mismatch still commits that target sample and stops; no descendant under the wrong prefix is committed. If admission ends early, its last target row supplies the bonus. Subsequent rounds reuse the same uncommitted-position tape. Thus arbitrary lookahead-dependent admission changes grouping, not the oracle outputs, provided every emitted token is sampled at its actual prefix and the tape is retained. Every round must make progress; zero admitted drafts still requires one valid target draw.

This pathwise argument does not require pretending AV ignores future draft randomness. By contrast, discarding a looked-ahead draw and resampling after a data-dependent truncation can bias output. Root's separate round99 finite fair-coin control demonstrates that issue; `root99-provenance.json` preserves independent ownership and hash. It is not evidence that current AV already has that failure.

## Native source delta and explicit gates

Seven copied target files and thirteen checked source quotations establish:

- Draft Gumbel currently uses a **draft noise salt**. With a logit cache it also mixes the proposal column through `spec_step_seed`. Those are deliberate separation under probability-ratio rejection, not the desired persistent target-only tape. Do not remove the salt globally while retaining native rejection.
- DSpark `_sample_logits` interprets `draft_logits is None` as **greedy argmax**. A no-cache shared-noise mode must explicitly separate probabilistic proposal selection from cache allocation. Merely setting None is incorrect. Current sample position is predicted-token-position minus1; the target uses the preceding-token position too, so ragged/compacted mapping must prove exact alignment.
- Markov bias depends on the previously selected draft token. Keep that full conditional proposal construction and unchanged weights. Confidence uses sampled-parent embeddings; the existing estimator/trained head predicts another acceptance policy. Preserve the actual AV policy as the initial control, disclose calibration drift, and never silently disable AV to claim a fixed-five comparison.
- Native verification applies target sampling parameters before computing target/draft local normalization, cumulative ratios, block residual masses, latest-passing-prefix acceptance and correction. A target sample cannot substitute within that existing law. The candidate instead needs an explicit new verifier path returning the same committed-token/count/cache interfaces.
- Target-only no-top-k/top-p sampling already routes to `gumbel_sample`; optional fused samplers and processors have separate eligibility. Initial admission must establish the actual reference route, dtype, masks, tie behavior and FP32/FP64 option. Watermarking, synthetic acceptance, unsupported custom/stateful processors and unproved mixed modes must retain the old path rather than be dropped.
- Request seeds are stored per request state, copied into drafter buffers; padded indices use-1. Absolute positions, seeded/unseeded initialization, slot reuse, restore/cancel, graph replay, partial AV rows, bonus alignment and rank synchronization remain native integration gates.

Pure prefix-dependent penalties/masks can conceptually belong to the oracle. Mutating processor state by evaluating rejected descendants is not automatically safe. Logprobs, prompt logprobs and stop/EOS metadata must continue to describe committed target outputs; this arm cannot claim all normalization disappears when callers request it. EOS and stop handling must use the same policy after committed tokens. Changed output samples need not equal native block-rejection samples at the same seed; the intended law/oracle is separately declared, while target score processing itself remains fixed.

## CPU evidence and remaining evaluation

`oracle_control.py` uses exact rational scores with finite positive clock vectors, a history-dependent ternary target and anchor/step-dependent drafter. Target samples are **precomputed at proposed prefixes**, including wrong descendants; the verifier uses those samples and stops at the first mismatch. Across64 tapes and three policies (fixed, future-token-dependent, future-noise-dependent admission),192 comparisons match separate target-only replay. This tests a finite pathwise construction, not continuous marginal sampling, native PRFs, AV code, tensor rounding, KV cache commits or GPU performance. The single-token acceptance expression is an independent exact-arithmetic counterexample to universal progress superiority.

The cheapest next source action is a concrete stable-seed/position/row-map adapter and processor/stop lifecycle admission table; then independent review of the functional oracle and native interface. No native implementation exists now. If authorized later, first compare target-only oracle and speculative path across batching, padding, AV truncation, retries, cancellation/slot reuse, prompt lengths, masks, EOS and both precision options. Verify target logits/cache semantics before timing.

Compare the best tuned native DSpark block baseline, an explicit shared-noise mode and FV86 where implemented, with the same target/AV policy and normal Mooncake/agent-p75 workloads. Measure exposed verifier time, full round time, accepted/committed lengths, request-level output counts, TTFT/ITL/goodput and paired uncertainty. Reject if oracle/lifecycle checks fail or lower progress/additional target noise erase savings. No new load harness or borrowed numeric promotion threshold is justified.
