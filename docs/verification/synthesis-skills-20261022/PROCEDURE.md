# CPU-only before/after skill experiment

1. Freeze the baseline skill text and after skill text with hashes. The evaluator freezes cases/rubric before seeing after text or outputs. D00 is a known development anchor; H01–H03 are synthetic held-out fixtures not shown to the skill author until after the skill is frozen.
2. Use fresh generator agents for before and after, with `fork_turns=none` so they do not inherit the long conversation or evaluator expectations. Use identical model/default effort, identical context/instructions and case packets; the skill text is the intervention. Record whether any setting cannot be matched.
3. Provide only generator inputs, the assigned frozen skill, and this neutral task: “Read the assigned skill and evidence packet. Produce a concise source-grounded hypothesis/evaluation handoff meeting the request. Do not browse or inspect other files, run tools beyond reading assigned inputs, execute experiments, or access evaluator files. Cite evidence IDs. Maximum 700 words per case. Zero candidates is allowed when justified.” Use individual fresh turns/agents per case if feasible; otherwise explicitly document multi-case shared-context confound.
4. Retain exact outputs and agent metadata in external `outputs/` paths, including errors. No candidate code, server access, neural training, model forward passes, GPU jobs, package mutation, cloud or repository writes occur. Reading/writing evaluation artifacts is the only execution.
5. Give evaluator anonymous labels where feasible and do not give it after skill text. Judge against frozen rubric with output quotations/evidence IDs before revealing version identity. Cases are synthetic and the evaluation is small; do not claim online retrieval quality or general performance gain.
6. Publish per-case findings, critical failures, discrepancies and limits. No silent rerun/drop of a bad output. If repeated for variance, retain and report all runs; no statistical confidence claim from this tiny sample. Archive original before/after hashes with the final comparison.

The files are in a shared filesystem; this is procedural separation, not an access-enforced sealed benchmark. The user-supplied TreeSpark plan is an example for evaluation, not authorization to execute its serving experiment.
