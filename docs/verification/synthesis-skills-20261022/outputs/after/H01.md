# H01 — one revised routing hypothesis

**Contract and evidence.** Improve burst serving with repeated prefixes, frozen weights, CPU design only; no fixed ROI floor. All evidence below is synthetic supplied material, not independently inspected papers or code.

**Hypothesis.** Adapt SCHEDULE-A's waiting-cost scoring to choose between the two independent engines during burst admission, using a transparent duration proxy and retaining session/cache locality when the estimated queue advantage is insufficient. The intervention replaces the router's fixed overload-spill decision, not the coupled DP/EP execution within each engine. A plausible gain is fewer waits at an overloaded session destination without excessive prefix recomputation [H01-E1–E3].

| Component | Dependencies and disposition |
|---|---|
| Waiting-cost per admitted-token policy | Reusable interface accepts any duration estimate. Specify the score and denominator explicitly; estimate demand using observed prompt-minus-hit tokens and queue occupancy, with unknown decode demand treated as uncertainty [H01-E1–E2]. |
| Learned future-length predictor | Unavailable: completion-length labels are absent. Omit training; do not present the proxy as an equivalent predictor or import the reported +22% [H01-E1–E2]. |
| Cache/session placement | Adapt existing router semantics and recorded routes. A destination's historical hit counts do not reveal another destination's counterfactual hits or eviction state [H01-E2–E3]. |

**Compatibility and target delta.** The score consumes an arrival's prompt length, observed affinity/cache evidence and engine queue occupancy, and emits one engine choice. Each engine retains ownership of its internal cache and coupled rank scheduling. Do not route DP ranks as independent GPUs: each destination is a four-GPU engine with coupled EP execution [H01-E2]. Prefix-hit information is usable at admission only if actually available then; otherwise use historical session observations or mark the required signal unavailable. Score queue pressure conservatively across uncertain decode costs and cache outcomes; retain affinity for unresolved decisions. This is a proposed heuristic, not a measured service-time model.

**What changed.** Queue occupancy enables a burst-pressure diagnostic; per-request hits allow examination of realized locality; session routes expose which engine received each request. These reopen a bounded revision of the prior cache-placement lead. They do not solve the absent eviction trace, completion labels or rank timing, so an additional “new cache placement” card would duplicate that lead and overstate readiness [H01-E2–E3].

**Cheapest falsifier.** Plan a CPU replay using the existing arrival/session replay: inspect burst queue imbalance, observed affinity hits and whether score decisions remain stable across explicit unknown decode/cache scenarios. Report reroutes, queue-pressure exposure, available-hit distributions and decision sensitivity. No feasible routing opportunities under the score, or dependence entirely on unavailable counterfactual hits, refutes this proposed implementation path. Decisions changing across unsupported service assumptions make the result inconclusive. Replay cannot honestly predict improved TTFT/TPOT using invented service or eviction costs [H01-E4].

**Matched evaluation design.** If later authorized, compare current session hash plus threshold spill with this policy on matched two-engine resources, arrivals, sessions, workload, initial cache conditions and output contract. Use existing end-to-end TTFT/TPOT measurements from actual runs, including tails under the same burst/load regime; record failure/completion counts, achieved throughput and cache effects. Preserve coupled DP/EP execution. Compare total policy benefit first; a queue-only ablation is optional if locality attribution changes the decision. Instrument decision-time signal availability and duration/cache outcomes missing from replay.

**Self-review.** Advance a CPU diagnostic, defer any service-gain claim. Strongest alternative: unknown decode length and coupled-engine execution dominate queue occupancy, while rerouting destroys valuable locality. Confidence is moderate in policy-interface reuse, low in benefit. The reported gain used fixed lengths, independent GPUs and a trained predictor without ablation, so it cannot supply local ROI [H01-E1]. No experiment was run.
