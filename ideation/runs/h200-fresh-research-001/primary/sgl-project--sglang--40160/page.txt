Motivation
DeepSeek-V4.1 verification rows from the same request score the same FP4 index-K cache. The existing Triton path decodes K independently for each query row; capacity-sized CUDA Graphs also leave substantial work on invisible positions.
This PR adds an opt-in SM90 grouped indexer that converts packed E2M1 to E5M2 in shared memory and uses FP8 WGMMA, reusing each decoded K tile across query rows. Hopper has no native MXFP4 MMA. The grouped path preserves the existing BF16 rounding points, ReLU, head weighting, and reduction order.
Changes
Optimize scale decoding in the existing SM90 Triton fallback.
Add a grouped CUDA path for H64/D128 request-major verification rows, with one query per warpgroup and shared K tiles of 64 positions.
Retain up to six decoded Q rows across 2/4/8 K tiles, with shape-dependent dispatch.
Compute
group_max_len
on device, skip completely invisible chunks/tiles, and write
-inf
. Partial tiles avoid reading invalid
req_to_token
entries.
Add a persistent scheduler: parallel device-side length loading, visible-chunk prefixes, a bounded resident CTA grid, and chunk sizing based on actual visible work. Q remains resident across assigned chunks from the same group.
Add a three-stage pipeline:
cp.async
loads packed tile i+2 while CUDA cores decode tile i+1 and WGMMA consumes tile i. Unaligned cache addresses retain a scalar-load fallback.
Extend registered tests for invisible tiles, partial groups, and CUDA Graph replay after changing lengths.
Dispatch and compatibility
fp4_index_logits_grouped_sm90(..., implementation=...)
accepts:
Value
Behavior
"auto"
(default)
Shape-dependent rectangular grid with Q residency and visibility skipping
"persistent"
Schedule visible chunks on a resident grid
"pipeline"
Persistent scheduling plus asynchronous packed-load/software-decode/WGMMA overlap
The grouped path remains opt-in; it is not enabled globally.
auto
does not automatically select persistent/pipeline. Measurements below show that the best mode depends on shape and visibility.
Scheduler metadata is CTA-local shared memory, recomputed on every invocation and graph replay. There is no CPU length readback, global allocation/counter, or request-slot scratch. Persistent modes support up to 1024 request groups and six rows per group, falling back to the single-tile path for larger inputs. Random physical slots, partial final groups, per-row lengths, compression ratios 1/2, and padded output/cache strides are supported.
Numerical behavior and resources
Packed FP4 block scales are factored into a common power-of-two scale, restored after FP8 accumulation, and followed by the existing BF16 dot rounding, ReLU, BF16 weighted-product rounding, FP32 head reduction tree, and final BF16 rounding.
