# Independent round60 source review

Agree with the scoped dispositions. These screens do not establish that all low-bit methods are exhausted or that the actual checkpoint has nonseparable scales.

The pinned input preparation quantizes an activation tile once, writes the routed packed scale, then writes the shared-expert layout from that same value. Remote expert input pulls are a different operation. The loader's repeat_interleave is inside _pack_scale called while loading a shard; it is not evidence of recurring per-decode conversion. Target source therefore closes the proposed duplicate-quantization premise without running a kernel.

FluxBin Eq11 explicitly uses per-basis row and column factors, allowing column folding before binary matvec. Its decomposition supplies that algebra. Native MegaMoE allocates output-row/K-group scales and accepts scale grids expanded at load; the format does not impose row/column separability. The exact2x2 determinant8 and [3,20] versus [3,12] control are sound. If checkpoint rows share a larger scale block, this example can be embedded across distinct blocks rather than assuming adjacent rows vary. It is a format counterexample, not inspection of actual learned tensors or a failure of FluxBin. Multiple factors/group-specific work remain possible repairs whose overhead needs evaluation. Native B200 MMA already consumes the low-bit representation; a dequantization-removal comparison against another consumer is inapplicable.

Vortex's selected text describes VQ codebooks, an added lookup unit/vector execution architecture, and the GPU lookup/accumulation bottleneck. The direct unchanged-format native-GPU port is unsupported. Rejecting that port does not reject the general product-table idea or prove a future exact GPU formulation impossible.

MpFA's selected lifetime argument borrows the opposite stage's score columns after softmax/PV have consumed them and before the next QK overwrite. Native MegaMoE's different pipeline has two accumulator stages followed by dedicated SFA/SFB columns. UTCCP copies precede the current MMA; the opposite accumulator can remain live in the epilogue until tmem_empty release. A safe overlay needs a complete lifetime/barrier design, including delayed epilogue reads. Simply moving addresses is unsafe. Also allocation is rounded by get_num_aligned_tmem_cols: removing logical columns does not necessarily reduce the allocation at a given tactic. Even crossing an allocation threshold does not by itself change this persistent kernel's grid/residency or service critical path. Keep the option unqualified until both lifetime and resource benefit have evidence.
