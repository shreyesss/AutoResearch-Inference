📌 Description

Both SM90 mega backends now accept MXFP8 expert weights: sm90_fp8_fp8_bf16_pull_cutedsl and sm90_fp8_fp8_bf16_push_cuda.

  • Input: a PrequantizedMoEWeights with float8_e4m3fn w13 / w2 and E8M0 per-1×32 scales (float8_e8m0fnu or uint8).
  • Conversion: done once, in preprocess_weights, to the 128×128 FP32 block-scale layout their FP8 kernels already run. Nothing is converted per forward.

Exactness. The block scales are powers of two, so the conversion only shifts each E4M3 value's exponent. It is exact except for elements that underflow E4M3: about 5e-5 of randn-like weights, with error at most half a subnormal step × the block scale. Re-quantizing with the existing amax/448 quantizers would instead re-round about 84% of elements.

Where it lives. The converter is host-only, in backends/mega/kernel/sm90/common/mxfp8.py.

Errors, no silent fallback. These raise MoEEpConfigError at init:

  • pull with fp8_scale_mode other than "blockwise"
  • E5M2 weights
  • NaN E8M0 scales
  • other pre-quantized recipes

Also fixes masked routing on the SM90 pull path. A -1 top-k route is never dispatched, so its combine row kept a previous launch's term, and TopkReduce summed it. That gave wrong output on any reused workspace. TopkReduce now derives its live-slot mask from the local routing.

Performance: 4× H200 SXM (NVLink), EP4.

  • DSv4 geometry: 384 experts, hidden 7168, intermediate 3072, top-6.
  • Pull FP8 blockwise, layer.forward p50 in µs, max over ranks.

Layer construction including conversion: 1.6 s with an MXFP8 checkpoint, 2.1 s with a BF16 checkpoint.
