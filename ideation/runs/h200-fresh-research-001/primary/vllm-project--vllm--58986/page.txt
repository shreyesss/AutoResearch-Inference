Purpose
GLM-5.3-Flash at TP4 uses 288 FP8 experts with a per-rank intermediate size of 512 and 128×128 weight blocks. H20 currently has no matching tuned configuration, so the default 64-row tile pads many expert assignments unnecessarily. Add a shape-specific configuration that selects 16- and 32-row tiles where measured faster and preserves defaults elsewhere. Also teach
benchmark_moe.py
to read the nested text configuration of the GLM-5.3-Flash architectures, so this shape can be benchmarked and retuned through the existing tool.
This does not replace the general heuristic in
#47593
. That PR's 16/64-row rule is an explicit control in the experiments: the small-batch improvement overlaps it and is credited to that approach. The new 32-row regions provide additional gains at the tested 640–1216 and 2560–3328 token sizes. Existing H20 configuration PRs
#44152
,
#44273
and
#54500
address other expert counts, shapes or quantization schemes; no open PR for this E=288, N=512 block-FP8 configuration was found.
The SM90 mHC correctness integration previously included here has been split into
independent PR #59129
. This PR now changes only the H20 MoE configuration and benchmark model-config handling. The two changes can be reviewed and merged separately. The full-model results below require the mHC fix in both benchmark arms; they are not measurements of an unrepaired dependency.
Test Plan
Retune/benchmark the model shape on H20 with the existing tool:
.venv/bin/python benchmarks/kernels/benchmark_moe.py \
  --model /path/to/GLM-5.3-Flash --tp-size 4 --dtype fp8_w8a8 \
  --batch-size 1 16 64 96 128 512 640 768 1024 1152 1280 2048 2560 2816 3072 4096
Independent measurements call that tool's
benchmark_config
directly, using 30 timing iterations (10 CUDA graph calls per iteration), seeds 1051/2077/3091, rotating arm order and changing routing between measurement iterations. All three arms receive the same seeds.
try_get_optimal_moe_config
selects the checked-in config through its normal nearest-entry lookup. Numerical comparisons against the previous default cover 31 batch sizes including lookup boundaries, three seeds each, BF16 activations and block-FP8 expert weights. This direct-function harness imports Ray but does not start a cluster.

Model quality and scope
O1+C1: GSM8K first 128, five-shot raw-completion diagnostic, greedy, concurrency 8, output cap 768:
121/128 correct
, all 128 requests successful, zero truncation. All six retrieval checks at 511/2047/2048/2049/4097/8193 tokens pass. The corrected control also scores 121/128 with zero failed or truncated requests. Prompts and dataset hashes match. Only 39/128 output texts are identical across these two runs; each arm uniquely answers three questions correctly. Previous C0 diagnostics scored 117/128 and 118/128; O1 scored 120/128 and 123/128. These subsets do not demonstrate an accuracy improvement or full-model equivalence. Whole-model exact repeatability is not asserted.
The full model was tested on the requested v0.30 release with the correctness backports. The upstream port was separately validated on H20 using main Python/Triton sources at
4a190dc51
plus this change: 35 batch sizes × three seeds = 105 numerical comparisons, including batch sizes 577, 1217, 2305 and 3329 immediately across configuration lookup boundaries. All pass with the same tolerance; maximum absolute difference 0.00015259 and maximum relative RMSE 0.0002718.
Main's MoE alignment API has an additional optional argument, so its MoE native extension was rebuilt from unmodified main sources with CUDA 12.9, GCC 12 and PyTorch 2.13. The other native extensions came from the release wheel. This validates the relevant main FP8 MoE path, not a full main-branch wheel or full-model serving on main. The initial attempt to reuse the release MoE binary failed on that ABI mismatch and was not counted as a successful test.
The mHC header repair and its regression test are submitted separately. GPU model validation remains v0.30. During the PR split, the complete performance-branch tree was verified identical to the previously validated O1-only commit
f2e71f998
. GPU tests were not rerun for this packaging-only split. B200, expert parallelism, other TP sizes/quantization formats, production traffic and long soak tests were not performed. Saturation throughput is not a production capacity/SLO guarantee.
AI assistance was used for investigation, code, tuning, test execution and this description. Human review has not been asserted.
