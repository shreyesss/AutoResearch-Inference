Motivation

SGLang currently supports FlashInfer's SM90 MXFP4 W4A16 CUTLASS MoE path, which was introduced in SGLang #24816 on top of FlashInfer #3084. FlashInfer #3738 adds a different Hopper path that dynamically quantizes activations to FP8 and runs MXFP4-weight x FP8-activation MoE GEMMs using Humming-style pre-MMA E8M0 scale fusion.

This PR wires that path into SGLang as an explicit opt-in:

--moe-runner-backend flashinfer_mxfp4 \
--flashinfer-mxfp4-moe-precision fp8

The existing default and bf16 behavior is unchanged.

Related work:

  • SGLang Add FlashInfer SM90 cutlass MXFP4 MoE backend (W4A16) for GPT-OSS + DeepSeek-V4 #24816
  • FlashInfer perf: optimize MXFP4xBF16 & INT4xFP8 and add MXFP4xFP8 CUTLASS MoE backend for SM90 flashinfer-ai/flashinfer#3738

FlashInfer version requirement

This integration intentionally targets the corrected API from FlashInfer #4431, where the FC1 and FC2 residual scales are FP32 tensors in local-expert order with shape [num_local_experts]. FlashInfer reuses its internal expert permutation to map those scales to routed rows, including global-to-local expert mapping under EP.

The original #3738 ABI briefly shipped before being reverted from FlashInfer 0.6.17 by #4411. It required downstream runtimes to construct routed-row residual tensors during every forward. SGLang does not support that older ABI.

The new option therefore requires both:

  • flashinfer-python >= 0.6.18
  • preprocess_moe_weights_for_sm90_mixed_gemm_humming

SGLang currently pins FlashInfer 0.6.17. This PR does not change that global pin. With 0.6.17, selecting fp8 fails immediately with an actionable error, while all existing FlashInfer paths remain compatible. The dependency, cubin, and JIT-cache pins should be upgraded together in a follow-up change.

GPU validation for this PR used FlashInfer 0.6.18 built from commit 8044d94bf9acc5369857baf88d28906bb32bf264, which contains the corrected API from FlashInfer #4431.

Modifications

Runtime selection and compatibility

  • Add fp8 to --flashinfer-mxfp4-moe-precision.
  • Select the new path only for flashinfer_mxfp4 on SM90.
  • Keep W4A16 as the default SM90 behavior.
  • Reject the SM90-specific fp8 option on SM100 and SM120 to avoid confusing it with their existing MXFP8 activation paths.
  • Require the corrected FlashInfer 0.6.18+ API instead of accepting the older routed-row residual ABI.
  • Pass use_wfp4afp8_humming=True only when the new path is selected. The keyword is omitted completely for FlashInfer 0.6.17 compatibility.

Weight preprocessing

  • Use preprocess_moe_weights_for_sm90_mixed_gemm_humming for both FC1 and FC2 during post-load processing.
  • Store the folded interleaved weight scales produced by FlashInfer.
  • Store residual * 64 as one FP32 value per local expert for FC1 and FC2.
  • Preserve GPT-OSS gate/up layout conversion and its existing padding rules.
  • Fill synthetic E8M0 scale padding from an existing scale in the same expert, preventing padding from changing that expert's min/max exponent range.
  • Support both the GPT-OSS MXFP4 quantization path and the DeepSeek-V4 MXFP4 expert path.

Kernel invocation

Construct the five Humming quant-scale slots expected by the corrected FlashInfer API:

  1. FC1 folded weight block scales
  2. FC1 per-local-expert residual scale, including the fixed 2^6 compensation
  3. Reserved scalar FC2 activation scale
  4. FC2 folded weight block scales
  5. FC2 per-local-expert residual scale, including the fixed 2^6 compensation

The existing TP/EP topology is forwarded to FlashInfer so it can map global expert IDs to the corresponding local residual scale.

Speed Tests and Profiling

The downstream benchmark uses the GPT-OSS-like shape from SGLang #24816: hidden size 4096, intermediate size 2048, 256 experts, and top-k 6. Each FlashInfer path was fully autotuned, followed by 5 warmup iterations and 30 timed iterations. The remaining token shapes were run in parallel with one independent shape per H20 GPU; each W4A16/W4A8 pair ran on the same GPU.

The benchmark can be reproduced with FlashInfer 0.6.18+:

PYTHONPATH=python:/path/to/flashinfer \
FLASHINFER_DISABLE_VERSION_CHECK=1 \
python test/manual/layers/moe/bench_mxfp4_sm90_kernels.py

Scope and Limitations

  • The implementation is SM90-only.
  • It is opt-in and does not change the default W4A16 path.
  • A coordinated FlashInfer 0.6.18 dependency update is required before production enablement.

fix(mxfp4): exclude pre-rounded hidden tail from Humming scale range
d312c83 
FusedMoE rounds hidden_size up (GPT-OSS 2880 -> 3072) BEFORE
create_weights whenever the flashinfer_mxfp4 backend is selected -- the
same gate that later selects _fi_kernel = "cutlass_sm90". The SM90
post-load processor therefore sees K_un = 3072 = K_pad, so the
preserve_expert_range fill guarded an empty region, while scale columns
[2880, 3072) INSIDE K_un keep the _UE8M0_ONE (127 = 2^0) buffer fill
that the naive-copy loader never overwrites.

Humming derives each expert's residual from its min/max E8M0 exponents.
The stale 127s sit far above any real per-expert max, so they inflate
the range, shift the residual, and perturb the REAL weights on repack.
Same story on w2's K rows.

Fix: FusedMoE records hidden_size_unpadded before the round-up,
create_weights stores it as _unpadded_hidden, and the w13/w2 scale
copies stop at the checkpoint's K (ceil'd to the 32-wide group boundary)
so the never-written tail is covered by the existing per-expert fill.
The tail's weight bytes are zeros (never written), so whatever scale
sits there multiplies zero -- numerically inert in the GEMM. The trim is
gated on preserve_expert_range, so the W4A16 path stays byte-identical.
The SM120 helper needs no change: it has no per-expert range statistic,
and its stale scales multiply zero weights.

Add test_humming_range_ignores_prerounded_hidden_tail, which builds the
production shape (buffers at 3072, checkpoint data to 2880, real scales
well below 127) and asserts the per-expert residual is invariant to the
tail content. The existing tests missed this twice over: they construct
the method at 2880 directly (never seeing FusedMoE's pre-round), and
their random scales span 125..130, which straddles 127.

409f07e 
Replace both hand-rolled FlashInfer version gates (try/except around

actually-installed API.
