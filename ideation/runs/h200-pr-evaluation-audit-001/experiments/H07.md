# H07 — Use indexed Humming GEMM with expert parallelism

Lane: **main**. Live-layout priority: **7**. Status: conditional plan; no GPU test or measured gain.

## Problem and causal hypothesis

After Humming is selected, Hopper EP can use grouped GEMM even though the indexed implementation better matches DeepSeek V4.1 expert execution.

## Applicability to our H200 deployment

Requires Humming, SM90 V4.1 MXFP4 experts and no all2all kernels or allgather_reducescatter. Inspect actual prepare/finalize backend. If existing env override selects indexed, test that before source changes.

## Isolated control and treatment

Use correctness-qualified H01 Humming/BF16 control. B: indexed dispatch only, retaining BF16 activations. Separate later arm for supported per-token FP8 activation with its own quality gate.

## Evaluation and predicted mechanism

E1: native agent-f75; E2: frozen Mooncake median/burst/cache-heavy. H200 capacity discovery and held-out confirmation in PROTOCOL.md.

Measure: Actual grouped/indexed dispatch; GEMM/packing/collective time; HBM; acceptance; numerical error and E1/E2 goodput.

## Why an additional evaluation is or is not needed

E1/E2 sufficient for performance. Upstream kernel checks and real-text quality are required for activation-format changes; they cannot be replaced by throughput tests.

## Decision and falsification

Apply [the preregistered protocol](../PROTOCOL.md). Confirm path and missing behavior before spending GPU time. Support requires correctness, predicted mechanism movement and a useful held-out SLO outcome. Reject an active, well-measured change with no useful endpoint gain or a correctness/tail regression. Mark absent-path, underpowered or failed-replay cases inapplicable/inconclusive; do not label them disproven. Correctness lanes establish only scoped correctness.

## Evidence limits

Conditional on H01; current backend is Marlin. Humming0.1.16 block-FP8 support conflicts with #61875; keep block-FP8 out of this arm.
