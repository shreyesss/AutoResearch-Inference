# H01 — One conditional routing hypothesis

**Decision.** Retain one hypothesis: adapt SCHEDULE-A's queue scoring to select between the two independent engines during bursts, incorporating an explicit cache-affinity cost. Confidence in applicability is moderate; benefit and implementation readiness remain low. This is reuse of an existing method, not a new algorithm. No minimum ROI or performance forecast is imposed.

**Transfer and intervention.** SCHEDULE-A separates its trained future-length predictor from a scoring policy accepting other duration estimates [H01-E1]. Reuse the latter at the router, comparing its choice against session affinity plus overload spill. Treat each four-GPU engine as a destination; its four coupled DP/EP ranks are not four independent servers [H01-E2]. Freeze neural weights. Completion-length labels are absent, so neither reproducing the trained predictor nor fitting a trustworthy completion-duration model is currently supported. Prompt length minus observed hit-prefix length supplies an uncached-prompt-work proxy, not measured service time. Queue occupancy supplies a load proxy, not remaining execution time. Evaluate these proxies explicitly as provisional estimates and keep unknown decode work visible.

The mechanism is to avoid burst queues when the expected wait reduction outweighs lost prefix reuse. Actual service benefit requires both meaningful route-choice disagreement and useful ordering of engine delay. Neither follows from the supplied records. Counterfactual hit lengths at the unchosen engine are also unknown: observed hits on recorded routes cannot simply be copied to hypothetical routes [H01-E2, H01-E3].

**What the new facts change.** Queue occupancy makes overload/imbalance exposure auditable, and per-request hit counts show whether repeat-prefix reuse occurs on observed routes. They justify revisiting the *diagnostic* part of prior cache-aware placement work [H01-E3]. They do not resolve eviction behavior, establish cache residence at alternate destinations, or justify a separate duplicate cache-placement candidate. Session route history identifies actual routing transitions. Missing completion lengths and rank timing still prevent calibrated service-time prediction and independent-rank modeling [H01-E2].

**Cheapest falsifier: CPU routing replay, proposed only.** Pin the supplied arrival/session/routing records, existing router threshold, retained hit counts and queue observations. Compare existing routing decisions with specified queue-score alternatives under explicitly varied unknown duration and alternate-cache assumptions. Report route disagreements, observed imbalance episodes, observed reuse and sensitivity. Do not recursively treat recorded queue occupancy as the state that a changed routing policy would have produced. If there is no relevant burst imbalance or no decision disagreement across plausible score settings, stop this intervention. If choices reverse under unmeasured decode/cache assumptions, return inconclusive and request those measurements rather than claim a win. Robust disagreement supports only advancing the diagnostic, not performance.

**Matched eventual evaluation.** Compare the existing router with the complete proposed policy on identical arrival/session replay, engine hardware/configuration, workload and warm-up/cache-state protocol. Keep the two engines and coupled rank topology intact. Use actual execution through the existing end-to-end TTFT/TPOT evaluator; compare burst-period latency distributions, completions and goodput only under an explicit service threshold. Check output/service consistency and record route choices, hits, actual engine service times and cache evictions to explain changes. This later execution requires separate authorization; none occurs now. The offline routing simulator cannot supply valid TTFT/TPOT gains from unknown GPU timing or eviction behavior [H01-E4].

**Self-review.** The strongest competing explanation is that decode-dominated or coupled-engine service and lost cache reuse overwhelm queue-score improvements. The fixture's +22% goodput does not transfer: it used independent GPUs, fixed lengths and its trained predictor without an ablation [H01-E1]. Advance only a bounded CPU diagnostic; defer service qualification. Coverage is limited to the four supplied evidence records, with no external discovery or implementation.
