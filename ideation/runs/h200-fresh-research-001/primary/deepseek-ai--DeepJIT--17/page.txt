Problem
deep_jit::cuda::Device::get_prop()
calls
cudaFree(nullptr)
once to make sure the CUDA context exists.
cudaFree
is prohibited while a stream is being captured in the global or thread-local mode. If the first device query happens inside a capture, it fails with
cudaErrorStreamCaptureUnsupported
(900), DeepJIT panics, and the capture is invalidated (
cudaErrorStreamCaptureInvalidated
, 901, at
cudaStreamEndCapture
).
Libraries hit this through lazy initialization: the runtime created by
create_lazy_jit
queries the device on first use. With DeepGEMM
main
(which pins DeepJIT
e5bdee2
), the first DeepGEMM call in a process fails if it happens inside
torch.cuda.graph
with the default capture mode:
Panic error (third-party/deep_jit/include/deep_jit/backend/cuda/device.hpp:15): cudaFree(nullptr) failed with CUDA error 900 (cudaErrorStreamCaptureUnsupported): operation not permitted when stream is capturing
  #0 deep_jit::cuda::Device::get_prop() at third-party/deep_jit/include/deep_jit/backend/cuda/device.hpp:15
  #1 deep_jit::cuda::CompilerOptions::default_options(deep_jit::Env const&, deep_jit::cuda::Device&) at third-party/deep_jit/include/deep_jit/backend/cuda/device.hpp:62
  #2 ... deep_gemm::init_jit(...)::{lambda} ...
  #3 deep_jit::LazyInit<deep_jit::Runtime<deep_jit::CUDA> >::operator->()
This is the only blocker I found. Once the runtime has been initialized, compiling and loading a new kernel during a global-mode capture already works.
Fix
Add a small RAII guard that switches the calling thread to
cudaStreamCaptureModeRelaxed
with
cudaThreadExchangeStreamCaptureMode
, and use it only around the one-time initialization in
get_prop()
. The previous mode is restored when the guard goes out of scope. This is the same mechanism as PyTorch's
c10::cuda::CUDAStreamCaptureModeGuard
, kept local so that
device.hpp
does not depend on c10.
Test
Adds a
CUDA device during graph capture
case to the CUDA test project:
A fresh
Device
is queried for the first time inside a global, thread-local and relaxed capture.
A runtime from
create_lazy_jit
is used for the first time inside a global capture.
Each case checks that the capture is still valid when it ends, and that the thread's capture mode is restored.

`Device::get_prop()` calls `cudaFree(nullptr)` once to make sure the CUDA
context exists. `cudaFree` is prohibited while a stream is captured in the
global or thread-local mode, so if the first query happens inside a capture
(e.g., the first library call under `torch.cuda.graph`), it fails with
cudaErrorStreamCaptureUnsupported and invalidates the whole capture.

Temporarily switch the calling thread to the relaxed capture mode for this
one-time initialization, and restore the previous mode afterwards.
