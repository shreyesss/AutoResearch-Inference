## Verdict

No blocker to the author’s **parked source-supported component**. Zero formal hypotheses and zero implementation/service qualification are appropriate. The source really performs an index-key projection on rows that the subsequent writer does not consume. The retained evidence does not establish an efficient smaller native operation.

The ratio-1 owner20 and later non-owning index sources do not provide the proposed parity-row elimination.

Replayed the author’s stdlib geometry script in this reviewer directory: eight cases and two naive-stride negatives reproduce its saved JSON exactly. This is an artifact-consistency check using the same symbolic implementation, not an independent implementation, source-kernel execution, numerical test or workload measurement.

## Strongest objection and integration boundary

The clearest remaining objection is implementation economics: removing mathematical rows does not imply removing native minimum tiles, a launch or weight reads. A fixed per-request capacity of ceil(n/2) gives no capacity reduction for singleton requests. GPU-selected boundaries and adaptive-verification row extents cannot be turned into a host-count synchronization or assumed five/six-row shape. The fastest next useful check is a concrete static-capacity mapping for actual admitted request spans, showing a smaller projected shape while preserving original token positions, slot identities and masked padding.

The compressor latent has another consumer. Its main-cache insertion must continue to see the original row layout; a K-only gathered view or separate compact buffer is required unless both contracts are deliberately changed and validated. Main-cache overlap may hide some of this work. PCP aggregation and graph replay metadata need their own admission; the author’s initial PCP1 scope is appropriate.

Changing M or the GEMM backend can change rounding/tactics even with row-independent real arithmetic. Valid K outputs, normalized/RoPE-rounded values, quantized cache payload/scales and downstream output behavior still need future differential checks. The current stdlib counts provide no such admission. Slot and position predicates must both survive; global odd/even row slicing is invalid for ragged starts.

## Donor and prior interpretation

FI5972’s selected interface explicitly requires BF16 packed keys and describes FP32 scoring without BF16 intermediate rounding. Its training-oriented fused selector is not a direct replacement for native paged MXFP4/FP8 scoring. I inspected the interface/validation patches, not every generated kernel or any compiled behavior. Treating materialization elimination as a reusable general component while declining the direct port is justified.

RouteRelay preserves attention evaluation only **within its selected support**; its sentinel trigger does not prove native support identity. The paper itself states that verifying the deterministic drift bound requires a full score row and reports slower unfused CPU execution. Existing AT01 seed/certificate work is the relevant overlap. The author correctly attributes the boundary-only K observation to target source inspection rather than to this paper.

The author’s workload/ROI limits and query/read-depth accounting remain appropriately bounded. No additional formal identity, numerical tolerance, gain forecast, harness or GPU execution is justified by this review.
