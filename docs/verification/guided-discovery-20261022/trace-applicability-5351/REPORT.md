## Precise minimal evidence needed

### Round49: static draft vocabulary screening

An already-existing representative output export would need exact target checkpoint/tokenizer/runtime identifiers, request ID/domain/split, complete **emitted token-ID sequence**, decoding controls (including any allowlist/grammar/bias), termination/truncation/failure status and workload version. Preserve request-disjoint train/holdout and domain coverage; forced fixtures must be marked/excluded from natural-distribution estimates. Exact IDs can screen empirical token coverage/outside-set bursts. They cannot recover the per-step target mass `p(S)`, drafter proposal mass, hypothetical restricted-block acceptance or latency without additional matched logits/proposal/progress evidence. Do not call empirical frequency a measured conditional mass.

### Round51: exact Engram projected-tuple recurrence

Need chronological **actually executed** rows after existing prefix-cache skips: request/round, rank/group, layer, phase (prefill/target decode/speculative verification), position, complete ordered24-table hash tuple, checkpoint/weight epoch, dtype/quantization/execution-shape contract and cache lifetime/order. Include rejected speculative rows, cross-request scheduling/interleaving and invalidation boundaries. Output IDs alone omit discarded speculative execution and prefill skipping. Prompt block hashes are not layer-specific Engram keys. Existing raw tokens might support a separately authorized reconstruction only with exact compression/hash semantics and execution history; neither is inferred here.

This would permit a bounded locality/capacity falsifier, not a native speed claim. No synthetic Zipf/repetition probe or automatic GPU capture is proposed as a substitute. Reopen retrieval on a specific applicable artifact path/index; keep the current directions deferred meanwhile.
