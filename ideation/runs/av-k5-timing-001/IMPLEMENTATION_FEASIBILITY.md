## Adaptive k5 compatibility and limitations

The existing controller is a plausible next lead, not yet qualified. `gpu/spec_decode/adaptive_verification.py:457–519` checks target backends for CPU/device query-length mismatch support and FULL graph support for variable per-request query lengths1–6; hard-wired DeepSeek attention is explicitly checked. `gpu/attn_utils.py:311–362` defines those checks. Additional attention groups outside the ordinary inventory must report ALWAYS. Ordinary `UNIFORM_BATCH` alone is insufficient.

The pinned v4.1 FlashMLA classes report the needed variable-query graph support: compressed-cache builder in `models/deepseek_v41/sparse_mla.py:221–227` and SWA builder in `models/deepseek_v41/nvidia/flashmla.py:38–47` report ALWAYS. The inherited backend API defaults to accepting device/CPU query-length mismatch unless overridden. The actual decode flattens query tokens (`nvidia/flashmla.py:200–204`), uses per-token sparse indices/lengths and passes `q.unsqueeze(1)` to FlashMLA (`:230–245`); it does not demand a uniform six-token sequence dimension there. `v1/attention/ops/flashmla.py:61–75` explicitly permits sparse FlashMLA on SM90 and SM100. This supports an SM90 eligibility case; it does not replace all-current-backend inventory or functional validation. Do not confuse the separate SM100-only Mega attention class with the H200 FlashMLA path.

Turning AV on changes target capture to variable-query decode and triggers startup cost calibration (`gpu/model_runner.py:717–739,1080–1086`). It retains full k5 proposal work. It uses stale confidence double buffering plus expected accepted-token benefit and startup cost tables (`adaptive_verification.py:256–355`), then redistributes the budget on GPU (`:397` onward). The controller chooses a budget per rank; subsequent existing DP max padding and graph-bucket rounding can consume the nominal saving. The baseline timing qualification must therefore expose target verification time, existing padding and the possible saving after synchronization; request-count opportunity alone repeats the C03 selection error. Thresholds, specific measurement windows, correctness checks and decisions belong to the evaluator designer.

There is also a specific interaction with the unmodified baseline: varlen target graph descriptors reserve `num_reqs=min(num_tokens,max_num_reqs)` (`gpu/cudagraph_utils.py:299–306`); the baseline FULL synchronization stores that padded request capacity (`gpu/dp_utils.py:201–210`); draft sizing multiplies it by5 (`gpu/spec_decode/speculator.py:519`). For illustration, five real requests with an AV target budget15 can select target bucket16/request-capacity16 and consequently draft80, whereas the fixed q6 target30 selects36/request-capacity6 and draft35. This follows the captured-bucket rules; it is not an observed AV run. It makes actual draft dispatch and end-to-end savings a necessary future qualification point. No C03 code is being reintroduced or combined with the current timing baseline.

The DeepInfer controller is related but not identical: its pinned `csrc/engine/mtp_varlen.hpp` also uses confidence and graph cost, with additional runtime forward-cost correction and sampler timing. No custom controller port is justified before testing the installed option. A shorter fixed k3 is source-permitted in the inspected DeepSeek config branch, which uses dspark_block_size only as an omitted-k default; it remains practically unqualified for this checkpoint, non-causal attention and graph/correctness behavior. The Qwen3-Omni equality assertion is not applicable to DeepSeek.

### Quantified static DP/draft-padding counterfactual

This is a conditional source calculation, not an observed AV run or timing prediction. Assume five real decode requests on each DP rank, one non-draft token plus up to five proposal tokens per request, and the original configured capture grid. The controller's `get_num_tokens` permits any additional draft-verification budget0–25 here (`adaptive_verification.py:294–351`); which budget wins its confidence/cost objective is unmeasured. The baseline snapshot `../c03-execution-001/A-exposure-final-snapshots/replica-0-rank-0.json`, capture-table hash `7350dd1c4d9722305338c2f222f99c713a6ba3a70f2d6cd5b30546987e821a09`, contains actual q6 target36/6 and q5 draft35/7,40/8,80/16,120/24,160/32 descriptors. `../c03-execution-001/startup-screen-A-replica-0.log` records configured sizes including8,16,24,32. AV target descriptors below are generated counterfactually from those configured sizes by the immutable varlen candidate rules; they are not present in that AV-OFF capture inventory.

|---|---:|---:|---:|---:|
| Existing fixed-k5 baseline |25|30|36 /6|35 /7|
| Conditional AV budget0 |0|5|8 /8|40 /8|
| Conditional AV budget5 |5|10|16 /16|80 /16|
| Conditional AV budget10 |10|15|16 /16|80 /16|
| Conditional AV budget15 |15|20|24 /24|120 /24|
| Conditional AV budget25 |25|30|32 /32|160 /32|

The budget10 case is a valid dispatch input under the source contracts: five requests and maximum query length6 fit a16-row/16-request varlen target descriptor. Compared with the fixed baseline it reduces target graph rows55.6% while increasing draft graph rows128.6%. These percentages describe row capacities, not FLOPs, milliseconds or throughput. A changed AV startup capture inventory must replace this counterfactual before any empirical conclusion.

No correcting AV-specific bypass was found in the inspected installed paths. Runner `gather_batch_req_state` substitutes the trimmed token total (`gpu/model_runner.py:1294–1297`), dispatches it with the scheduler's real request count and query bound (`:1727–1775`), and retains the returned DP sync. Compaction/reallocation modifies query/token buffers, not that sync (`:1388–1423`). Normal `sample_tokens` passes it unchanged to the speculator (`:2221–2235`). FULL sync sets its request count from the selected descriptor (`gpu/dp_utils.py:201–210`); the shared helper multiplies that capacity by5 (`gpu/spec_decode/speculator.py:519–529`); inherited DFlash proposal dispatches the resulting uniform q5 batch (`gpu/spec_decode/dflash/speculator.py:495–511`). DFlash's graph manager is not switched to varlen. The installed model-state deviation changes inner PIECEWISE replay handling; its FULL early return (`source/installed-image/.../model_state.py:452–458`) neither replaces this DP sync nor fixes draft sizing.

The same nominal k5 therefore does not imply unchanged draft execution cost when enabling AV. Later qualification must observe both target and draft descriptors after DP synchronization, including no-budget and full-budget boundaries. This note authorizes no AV-ON run, controller modification or combination with the rejected C03 performance candidate. Current AV-OFF timing remains useful and unchanged.
