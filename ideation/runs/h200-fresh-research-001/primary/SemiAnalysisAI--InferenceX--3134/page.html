Sweep 1 · failed at engine start · Run 35012494184 · c1 and the c128 eval-only job

The Rust frontend hit its 3600 s readiness deadline while the engine was still loading weights: 19/48 safetensors shards at ~170 s/shard from the VIRTIOFS-mounted HF cache. vLLM logs Auto-prefetch is disabled because the filesystem (VIRTIOFS) is not a recognized network FS on this nightly. The same files loaded in ~10 minutes (~12.5 s/shard) on deepseekv41-flash-0909 in run 34504985992; both images select the same Marlin MXFP4/MXFP8 kernels, so the difference is in the lazy mmap load path. The H100 arm (Lustre cache, auto-prefetch on) already passed its eval job on the same nightly, and no Blackwell arm has timed out.

Change (29b2f4f): runners/launch_h200-dgxc-slurm.sh exports VLLM_SAFETENSORS_LOAD_STRATEGY=prefetch (forwarded by the shared script as --safetensors-load-strategy, so shards stream into page cache via parallel readers; the 475 GiB checkpoint fits the ~1 TiB host RAM) and VLLM_ENGINE_READY_TIMEOUT_S=7200, matching the GB300 launcher. No serve-flag or grid change; other SKUs do not set the variable.

Next: rerun the full sweep.
