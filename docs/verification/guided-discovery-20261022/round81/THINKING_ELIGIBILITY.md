# CF59 round81 additive eligibility clarification: thinking labels

Original round81 manifest abbb0f04a1a39931d482f777a74b4ac86c97d45404e0fb88663c3b8c00bbb3fa remains unchanged. Same CF59, deferred; no event, implementation or workload feature was changed.

“Thinking high/75” is not sufficient evidence that `needs_logits_processing` is true. In pinned c455 chat protocol, `reasoning_effort` is passed into template kwargs and can set `enable_thinking`. The separate `thinking_token_budget` field defaults to None and is forwarded separately to SamplingParams. ThinkingBudgetState requires configured start/end/natural-end IDs; when disabled it returns False. When enabled, add_request returns whether the separate budget is non-None. The sampler ORs this result with other processors' activation flags. Neither temperature1/top_p1 nor a thinking label alone establishes the complete flag state.

The earlier retained Bitlane sweep builder reinforces this distinction: its allowed request keys contain thinking/effort but not thinking_token_budget. Gateway payload sets reasoning_effort; direct payload sets engine-specific chat_template_kwargs. These saved builder files are not an executed exact c455 HTTP payload or proof that an external gateway never translates options. Therefore we do not conclude either that the narrow first arm excludes all agent-p75 traffic or that it is certainly active for that traffic. Effective per-request fields/flags remain the relevant observation; no requested thinking feature should be disabled to create eligibility.

There is also a source-backed way to avoid treating any active budget as automatically incompatible. The actual `apply_thinking_budget` body launches two Triton kernels: committed marker-cache update, then forcing the end-marker logits. Its explicit state is the logits tensor, request token/history metadata and its own cached marker positions. It does not call MXFP8 GEMM or WorkspaceManager and does not receive context hidden/projected tensors. This removes a particular shared-GEMM-caller premise for this native processor, but does not alone audit every other processor invoked by the broader flag-true branch, prove allocator/capture safety or authorize a broadened adapter. A future selective arm can inspect the actual active native processor set instead of requiring all logits processing globally absent.

No new query, runtime/native import, tensor operation, source execution or numerical test was needed. Six exact source/builder artifacts are retained; original source and frozen81 were not modified. This is an additive source qualification, not an extra hypothesis or a performance result.
