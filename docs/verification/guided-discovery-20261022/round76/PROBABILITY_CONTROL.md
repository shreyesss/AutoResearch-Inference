# Draft-temperature probability contract: independent scalar control

Executed exact rational arithmetic for a standard single-token rejection sampler. This is a necessary sanity example for keeping proposal, acceptance and residual distributions consistent. It is not an implementation of DSpark block rejection and does not test native finite-precision kernels, RNG or performance.

Target p=(2/5,7/20,1/4). Original q=(9,4,1)/14 corresponds to logits log(9,4,1) at temperature1. Temperature2 gives q_new=(3,2,1)/6 exactly. Both unchanged baseline and consistently updated sampler return p exactly under the standard rejection formula. Sampling q_new but using old q for acceptance and residual produces total variation4/45. Updating acceptance while retaining old residual still produces total variation1/102. Updating residual alone also fails. These are deterministic finite-outcome calculations, not Monte Carlo p-values or evidence that the target implementation currently has this bug.

The calculation expands the complete output probability: proposal(v)*min(1,p(v)/q_accept(v)) plus total rejection probability times normalized positive part of p-q_residual. No added precision noise or invented cost/acceptance benchmark is present.

Root separately read the selected pinned DSpark/gumbel/rejection source copies while the author investigation was in progress. The existing draft cache deliberately stores pre-temperature logits to preserve cache dtype; verifier statistics, accepted-token probabilities and residual kernels reconstruct q using the target request-temperature argument. A future separate proposal temperature must reach all corresponding q consumers. Scaling the raw cache first can change rounding/dtype behavior and needs a separate equivalence contract. Actual target p, sampling parameters and residual semantics must remain unchanged.

Source reading also shows acceptance prediction occurs before Gumbel temperature division. Modified proposal distributions and sampled parents can invalidate existing confidence/AV calibration even if sampler correctness is preserved. Treat that scheduling question separately and declare the controlled effective policy. A common-prefix overlap objective and held-out split do not by themselves measure online block acceptance when the new policy visits different prefixes. These objections were sent to the author before finalization; this packet is a transparent design control, not a blinded independent review of the final hypothesis.

No GPU, model import, native code execution, serving change, new hypothesis identity or canonical mutation occurred. Future native block-verification and distributional tests remain required. This probe is useful for rejecting incomplete probability plumbing; it supplies no throughput forecast.
