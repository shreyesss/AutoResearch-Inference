Summary
Round 2 of the Hopper native BF16 MegaMoE backend (
sm90_bf16_bf16_bf16_push_cake
): pre-reduced combine wire, protocol fixed-cost levers and a re-rendered grouped-GEMM epilogue. Follow-up to
#5958

sm90_bf16_bf16_bf16_push_cake

MoEEpLayer
). Part of
#4254

#5708

What changed
Combine wire
(the only numerics change; deterministic)
combine_wire="prereduced"
(new): each expert rank pre-reduces, in fp32 (
fmaf
) and in ascending route order, the routes of a token that it computed, rounds once to bf16 and publishes one row per (token, source rank) into the owner's inbox. The owning rank sums the per-rank rows in ascending rank order in fp32 and rounds once. Inbox traffic drops from
T * top_k
rows to
T * world
rows (EP8, top-8: 7.0 to 4.6 rows per token on uniform routing).
combine_wire="prereduced_hilo"
(new): the pre-reduced row plus a bf16 residual row for multi-route groups; a precision-conservative variant kept selectable (it is not faster).
combine_wire="per_route"
: the round-1 wire (one row per route), unchanged and bitwise identical to
feat(cake_mega_moe): SM90 native BF16 MegaMoE expert compute through MoEEpLayer (sm90_bf16_bf16_bf16_push_cake)
#5958
.
Default
(
combine_wire=None
, env unset):
per_route
when the per-rank token capacity is
<= 8
,
prereduced
above.
FLASHINFER_SM90_CAKE_BF16_COMBINE_WIRE=prereduced|prereduced_hilo|per_route
overrides. All ranks must agree; the construction-time allgather rejects mismatches with
MoEEpConfigError
.
Determinism: fixed accumulation order (routes ascending within a rank, ranks ascending across ranks), no fp32 atomics on outputs or partial sums; bitwise run-to-run; eager == CUDA graph.
Protocol fixed-cost levers
(output bit-identical to round 1): publish scratch self-resets instead of four per-round memsets; the pre-reduced worklist is built inside the compact pass (one launch fewer); grid completion counts participating blocks only; compact assigns rows by static grid stride instead of an atomic work queue; publish groups are split across blocks at decode sizes.
Grouped-GEMM epilogue
(sealed sources re-rendered from the generator; output bit-identical): bf16x2 pack, quad transpose and 16-byte stores (FC1+FC2 +4.5 % at T >= 1024; no register or spill change, 168 regs).
Validation
Numerics
Against an independent fp32 reference over the 290 EP1/EP2/EP4/EP8 test cases (max-abs, mean-abs, rel-L2 per case): the pre-reduced wire's aggregate mean-abs is 0.000888 vs 0.000974 for round 1 and rel-L2 0.00341 vs 0.00365; 6/290 cases have a max-abs one bf16 ulp above round 1 (outputs with |y| in [2, 4)), with lower mean-abs and rel-L2 on those cases. Per-case rel-L2 differs from round 1 by at most +0.33 %. The
atol=rtol=1e-2
test gate is unchanged. With the per-shape default, rounds with per-rank token capacity
<= 8
keep round-1 numerics bitwise.

Format agreement and ordered completion constrain the change. However, invalid configuration on one rank can delay startup across the group. No new externally reachable exploit was established, and deployment-specific exposure remains uncertain.
Retained concerns
Low · reliability · inferred:
New wire resolution and prerequisite checks run before guarded collective initialization. If only one rank rejects its environment override or fused-tail configuration, that rank exits while peers can wait in the weights-and-buffers collective. This weakens coordinated startup failure containment. The integrated backend bounds the wait by its configured timeout and cleans up locally; bounded recovery for direct runner callers is not established.
Security review details
Security Blast Radius
inferred
— The supported exposure is the participating EP group and layers sharing its matching process-level workspace. The startup failure can affect peers despite originating on one rank. Tenant and service boundaries beyond that group are not established by the supplied deployment evidence.
Security Findings and Attack Paths
inferred
— The supported failure path requires control of rank-local constructor or environment settings and ends in disrupted group initialization. The inspected flow does not establish privilege gain or a cross-tenant write. The canonical security input contains no retained findings, but its coverage remains unknown.
Trust Boundaries and Controls
observed
— The peer-memory protocol relies on rank agreement and trusted layout addresses. New grouping bounds checks abort on invalid metadata, while owner-slot derivation and tagged completion constrain legitimate publishing. These controls are protocol checks, not isolation from a compromised participating rank.
Resilience and Maintainability Implications
observed
— The integrated backend configures an all-rank-consistent initialization timeout and destroys the pipe when runner construction raises. The valid-wire mismatch test specifies coordinated rejection followed by successful construction of a consistent layer; it does not demonstrate recovery from rank-local invalid configuration, and was not executed in this review.
Hardening Proposals
proposed
— Resolve and validate wire prerequisites inside a guarded all-rank initialization phase so a local configuration error is reported before peers enter later collectives. Make direct-caller timeout and cleanup responsibilities explicit.
proposed
— Use the effective resolved wire in workspace identity, or document and enforce immutable environment selection while pooled workspaces remain live. This would make numerical-mode selection and fallback behavior predictable without treating existing self-consistent reuse as a demonstrated isolation defect.

The combine wire (expert rank -> token owner) is selected by
`combine_wire` on the config (`None` reads
`FLASHINFER_SM90_CAKE_BF16_COMBINE_WIRE`, default `prereduced`) and must be
the same on every EP rank (checked with an allgather at init; a mixed pipe
raises on every rank). `prereduced`: the expert rank pre-reduces all routes
of a token that landed on it in fp32 (`fmaf` in ascending route order), rounds
once to bf16 and sends ONE row per (token, source rank) into the owner's
top-k inbox (slot = the group's smallest route index); the owner sums the
<= ep_size rows in ascending source-rank order in fp32 and rounds once.
`prereduced_hilo`: as `prereduced`, but a source rank holding >= 2 routes of a
token sends its fp32 partial as two bf16 rows (hi, and the residual `p - hi`
in the slot of its second-smallest route index) so no group partial is rounded
to bf16; single-route groups are `bf16(w * y)` exactly as the per-route wire.
`per_route`: one `bf16(fp32(y_k) * w_k)` row per route, summed over k by the
owner (the original wire, kept for A/B comparison; the only wire that also
runs the vendored three-kernel tail). Both wires are deterministic (fixed
reduction order, no floating-point atomics; repeated calls and CUDA-graph
replay are bitwise identical) but not bitwise identical to each other: the
pre-reduced wire rounds each element twice instead of top_k + 1 times. The
section tests run every routing pattern under both wires, including the
pre-reduce-specific cases (all K routes of a token on one remote rank, all on
the local rank) and the wire-mismatch rejection.

feat(cake_mega_moe): pre-reduced BF16 combine wire and fixed-cost lev…
…
dfc9193
…ers for the SM90 MegaMoE backend

Round 2 of the Hopper native BF16 MegaMoE backend
(`sm90_bf16_bf16_bf16_push_cake`,
flashinfer-ai#5958
). Part of
flashinfer-ai#4254
, follow-up to
flashinfer-ai#5708
.

Combine wire (the only numerics change; deterministic):
- `combine_wire="prereduced"`: each expert rank pre-reduces, in fp32 and in
  ascending route order, the routes of a token that it computed, rounds once
  to bf16 and publishes one row per (token, source rank); the owning rank sums
  the per-rank rows in ascending rank order in fp32 and rounds once. Inbox
  reads drop from T*top_k rows to T*world rows.
- `combine_wire="prereduced_hilo"`: the pre-reduced row plus a bf16 residual
  row for multi-route groups (precision-conservative variant).
- `combine_wire="per_route"`: the round-1 wire (one row per route), unchanged.
- Default (`combine_wire=None`, env unset): `per_route` when the per-rank
  token capacity is <= 8, `prereduced` above. `FLASHINFER_SM90_CAKE_BF16_COMBINE_WIRE`
  overrides; all ranks must agree (verified at construction).
- Fixed accumulation order (routes ascending within a rank, ranks ascending
  across ranks), no fp32 atomics on outputs or partial sums; bitwise
  run-to-run and eager == CUDA graph.

Protocol fixed-cost levers (output bit-identical to round 1): publish scratch
self-resets instead of per-round memsets, the pre-reduced worklist is built
inside the compact pass, grid completion counts participating blocks only,
compact assigns rows by static grid stride, publish groups are split across
blocks at decode sizes.

Grouped-GEMM epilogue (sealed sources re-rendered; output bit-identical):
bf16x2 pack, quad transpose and 16-byte stores.

Measured on one 8xH100 node (CUDA graph, CUPTI, paired same-process A/B
against the round-1 backend, 35 benchmark rows, two independent sessions):
geomean 1.031, 33/35 rows improved (best EP4 T=4096: 1.12); against the split
nccl_ep + CUTLASS BF16 baseline geomean 1.55. Precision against an independent
fp32 reference: aggregate mean-abs and rel-L2 below round 1 on every column;
the atol=rtol=1e-2 test gate is unchanged.

Tests: frozen-sources seal, EP1 (all wires, per-shape default, duplicate-rank
and all-local routing, wire mismatch), EP2/EP4/EP8 torchrun;
`run_tests.sh sm90_bf16_push_cake`. Docs: architecture and runbook updated
(wire semantics, determinism note, benchmark `--combine-wire` flag).

## 📌 Description

The SM90 BF16 Cake MegaMoE backend loads its generated CUDA sources and
manifest at runtime for JIT compilation. However, these files were not
registered in `pyproject.toml`.

Because `include-package-data` is disabled, the following resources were
excluded from built distributions:
```
  - `cake_bf16_megamoe/src/*.cu`
  - `cake_bf16_megamoe/src/*.json`
```
Source-checkout tests passed because the files were available in the
repository, but installed-package tests failed because the generated
manifest and CUDA sources were missing.

  This PR:

- Adds the SM90 BF16 Cake MegaMoE CUDA sources and manifest to
`[tool.setuptools.package-data]`.
- Adds a regression test to ensure the package-data declarations are not
removed accidentally.
  - Does not change kernel behavior or generated source contents.
